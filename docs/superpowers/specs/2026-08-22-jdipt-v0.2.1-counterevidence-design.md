# JDIPT v0.2.1 Counterevidence Gate Design

## 1. 목적

JDIPT v0.2.0은 `Legal Issue Mapping → Legal Interpretation → Logic Validation → Answer Rendering` 흐름으로 법적 대상·분류, 본칙·예외, 중복규율, 규율공백, 논리적 타당성, 출력구조와 URL provenance를 검증한다.

배포 후 실사례에서 다음 한계가 확인되었다.

- 잠정 결론을 뒷받침하는 법률·시행령·시행규칙 조문은 정상적으로 수집했다.
- 현행 공식 URL과 조문 인용도 정상적으로 검증했다.
- 그러나 결론과 긴장관계에 있는 시행규칙 별지서식의 `신설·증설` 문구를 수집·검토하지 않았다.
- 그 결과 `신축으로 한정하는 문언이 없다 → 기존 건축물도 가능`이라는 논증이, 관련 법령체계 안의 반대방향 자료를 해결하지 않은 채 확정 결론으로 출력되었다.

v0.2.1의 목표는 **잠정 결론을 확정하기 전에 그 결론을 무너뜨리거나 제한할 수 있는 직접적인 법적 근거가 관련 법령체계 안에 존재하는지 확인하고, 발견된 근거를 해결하지 않은 상태에서는 확정 결론을 내리지 않도록 하는 것**이다.

이 기능은 `항상 찬반 자료를 하나씩 찾는 양비론 생성기`가 아니다. 관련성이 합리적으로 예상되는 반대방향 자료를 탐색하고, 실제로 발견된 자료만 법적 위계·기능·본문과의 관계를 검토한다.

## 2. 범위

### 포함

- 잠정 결론과 충돌하거나 결론을 제한할 수 있는 법적 근거 탐색
- 하위법령·별표·별지서식·신청서상 법적 카테고리의 관련성 확인
- `규정이 없다`, `명시적 제한이 없다`, `적용 제외가 없다`와 같은 부재 논증의 강화 검증
- 발견된 반대근거의 법적 위계·위임근거·기능 평가
- 해결되지 않은 반대근거가 있는 경우 결론 강도 하향 또는 `확인 필요` 처리
- E39/E40 신규 회귀 시나리오
- 정적 validator 계약 동기화

### 제외

- 항상 찬성·반대 자료를 대칭적으로 수집하는 요구
- 별지서식 문구를 법률·시행령과 동일한 법적 효력으로 취급하는 규칙
- 새로운 외부 법률 데이터 소스 추가
- MCP 서버 기능 변경
- 자동 Skill 선택 복원
- 기본 4단 출력 구조 변경
- v0.2.0 Golden Case 논리 변경

## 3. 설계 원칙

### 3.1 기존 4단 아키텍처 유지

v0.2.1은 별도의 최상위 파이프라인 단계를 신설하지 않는다.

기존 구조는 그대로 유지한다.

```text
Legal Issue Mapping
        ↓
Legal Interpretation
        ↓
Logic Validation
        ↓
Answer Rendering
```

Counterevidence 검증은 다음 두 위치에 분산된 필수 하위 Gate로 구현한다.

1. `Legal Issue Mapping + Source Policy`: 관련 반대방향 자료를 탐색하고 적용 규범 지도에 포함한다.
2. `Logic Validation`: 이미 발견된 중대한 반대근거를 해결하지 않은 결론을 BLOCK한다.

이 방식은 v0.2.0 아키텍처를 깨지 않으면서 root cause를 직접 보완한다.

### 3.2 탐색과 법적 평가를 분리

반대근거 발견 자체는 결론을 뒤집는 이유가 아니다.

내부 순서는 다음과 같다.

```text
잠정 결론
→ 결론 제한 가능 자료 탐색
→ 자료의 법적 위계 확인
→ 위임·준용·본문과의 연결 확인
→ 자료의 법적 기능 확인
→ 잠정 결론과 실제 충돌하는지 판단
→ 충돌 해소 또는 결론 강도 조정
```

예를 들어 별지서식에 `신설·증설`이라고 적혀 있다는 이유만으로 기존 건축물 전환이 불가능하다고 단정하지 않는다. 해당 문구가 법률상 `설립`의 범위를 제한하는지, 단순 신청 유형 분류인지, 상위법과 조화롭게 해석할 수 있는지를 검토한다.

### 3.3 부재 논증은 강화 검증

다음 유형의 잠정 논거는 Counterevidence 탐색을 강하게 트리거한다.

- `법령에 ○○라고 규정하지 않는다`
- `신축으로 한정하는 문언이 없다`
- `적용 제외 규정이 없다`
- `금지 규정이 없으므로 가능하다`
- `별도 제한이 없으므로 적용된다`

규정의 부재를 적극적 결론의 근거로 사용할 때는 직접 조문뿐 아니라 관련 하위법령·위임규정·준용규정·별표·별지서식까지 확인할 필요가 있는지를 내부적으로 검토한다.

## 4. Legal Issue Mapping 변경

`skills/law-interpretation-request/references/legal-issue-mapping.md`의 적용 규범 지도에 다음 역할을 추가한다.

- 신청·승인·등록 절차 규정
- 별표·별지서식
- 법정 신청 유형 또는 처분 유형
- 잠정 결론을 제한하거나 반대방향으로 작용할 수 있는 규정·서식

모든 사안에서 별표·별지서식을 무조건 조회하지 않는다. 다음 조건 중 하나가 있으면 우선 검토한다.

1. 사용자의 쟁점이 허가·승인·신고·등록·변경승인 등 절차적 법적 효과에 관한 경우
2. 법률 본문이 시행령·시행규칙 또는 서식에 세부 절차를 위임하는 경우
3. 잠정 결론이 `명문 제한 없음` 또는 `규정 부재`에 의존하는 경우
4. 법적 결과가 `신설`, `증설`, `변경`, `신규`, `기존`, `전환` 같은 절차적 분류에 따라 달라지는 경우

### 4.1 문제 발생 지점 강화

현재 `문제 발생 지점`은 본칙/예외, 중복규율, 규율공백, 요건의 필요·충분 관계 등을 특정한다. v0.2.1에서는 다음 유형도 추가한다.

- 본문에는 제한 문언이 없지만 하위 규정·별표·별지서식에 다른 분류 문언이 있는 경우, 그 문언이 상위법상 법적 개념의 범위를 실제로 제한하는지가 결론을 가르는 지점인지 확인한다.
- 동일하거나 유사한 용어가 법률 본문과 시행규칙·서식에서 다른 수준의 의미로 사용될 가능성이 있으면 의미·기능을 구분한다.

실사례의 좋은 문제 발생 지점은 다음과 같다.

> 별지 제19호서식의 `지식산업센터 신설`이 건축물의 물리적 신축만을 의미하는지, 아니면 기존 공장 건축물을 최초로 지식산업센터로 전환하는 경우도 포함하는지.

`법에 신축 제한이 없으므로 가능` 수준에서 분석을 종료하면 안 된다.

## 5. Source Policy 변경

`skills/law-interpretation-request/references/source-policy.md`에 `Source Completeness / Counterevidence Gate`를 추가한다.

### 5.1 잠정 결론 후 최소 확인 범위

잠정 결론을 세운 뒤, 관련성이 합리적으로 예상되는 범위에서 다음을 확인한다.

1. 결론을 직접 뒷받침하는 근거
2. 결론을 명시적으로 제한하는 규정
3. 결론과 긴장관계에 있는 하위법령·별표·별지서식
4. 정의·준용·위임에 의해 반대방향으로 연결될 수 있는 규정

`반대근거 1개를 반드시 찾아야 한다`는 요구는 두지 않는다. 존재하지 않는 반대근거를 생성하거나 억지로 균형을 맞추는 것을 금지한다.

### 5.2 탐색 키워드

법적 결과를 결정하는 용어가 있으면 찬성 방향 용어만 사용하지 않고 반대·제한 가능성을 드러내는 관련 용어도 탐색한다.

실사례에서는 다음과 같은 용어군이 해당한다.

- 지식산업센터
- 설립
- 신설
- 증설
- 변경승인
- 기존 건축물
- 전환
- 설립승인
- 설립완료신고

키워드 목록을 하드코딩하지 않는다. 질문과 확인된 조문에서 법적 분류를 가르는 용어를 파생한다.

### 5.3 자료의 법적 무게

수집된 자료를 동일한 법적 무게로 취급하지 않는다. 최소한 다음을 구분한다.

- 법률
- 시행령
- 시행규칙
- 별표
- 별지서식
- 행정규칙
- 공식 해석례·질의회신

하위 자료가 상위법에 없는 제한을 독자적으로 창설하는 것처럼 해석하지 않는다. 먼저 위임근거, 규정 기능, 상위법과의 정합성을 확인한다.

## 6. Logic Validation 변경

`skills/law-interpretation-request/references/logic-validation.md`에 다음 BLOCK 규칙을 추가한다.

> 잠정 결론에 중대한 영향을 줄 수 있는 반대 법적 자료가 현재 실행에서 실제로 발견되었는데, 그 자료의 의미·법적 기능·상위법과의 관계를 해결하지 않은 채 확정 결론을 내리면 BLOCK한다.

BLOCK 발생 시 다음 중 하나로 처리한다.

1. 반대근거의 적용 여부를 해석하여 충돌을 해소한다.
2. 추가 공식자료를 확인한다.
3. 해결할 수 없으면 결론을 조건부로 낮춘다.
4. 결론에 필수적인 사실이 부족하면 `확인 필요`로 표시한다.

### 6.1 금지되는 자동 추론

다음 두 방향 모두 금지한다.

```text
상위법에 명시적 제한 없음
→ 따라서 무조건 가능
```

```text
별지서식에 제한적으로 보이는 문구 있음
→ 따라서 무조건 불가능
```

정답은 자료의 관계를 해석한 뒤 결정해야 한다.

## 7. SKILL orchestration 변경

`skills/law-interpretation-request/SKILL.md`의 작업 순서와 MCP 조사 절차를 최소 수정한다.

### 작업 순서

Legal Issue Mapping 단계에서 잠정 결론을 확정하기 전에 다음을 추가한다.

- 결론을 제한할 가능성이 있는 관련 하위법령·위임·준용·별표·별지서식을 Source Completeness Gate에 따라 확인한다.
- 특히 `명문 제한 없음`, `규정 부재`를 적극적 결론의 근거로 사용하는 경우 이 검토를 생략하지 않는다.

### MCP 조사 절차

기존 `search_law → get_law_text → decisions → discover_tools` 흐름을 유지한다.

필요한 별표·별지서식 또는 세부 자료를 직접 조회할 도구가 보이지 않으면 기존 규칙대로 `discover_tools`를 통해 가능한 공식 자료 조회 기능을 찾는다. MCP가 해당 자료를 제공하지 않으면 공식 법령 페이지를 보조적으로 사용한다.

MCP 기능 자체는 변경하지 않는다.

## 8. 출력 동작

기본 4단 H1과 법제처 1~3 H1은 변경하지 않는다.

Counterevidence Gate는 내부 절차이며 별도의 사용자용 `반대근거` 섹션을 강제로 만들지 않는다.

반대근거가 결론에 중요하면 `# 3. 검토이유` 안에서 자연스럽게 설명한다.

예:

- `한편 시행규칙 별지 제19호서식은 신청 유형을 신설·증설로 구분하고 있으므로, 여기서 신설의 의미가 건축물의 물리적 신축에 한정되는지는 추가로 해석할 필요가 있습니다.`

해결되지 않은 경우 `# 2. 검토결론`에서 확정적 표현을 낮춘다.

예:

- `현행 법률 본문만으로는 기존 건축물이라는 이유만으로 설립승인을 배제하기 어렵지만, 시행규칙 별지서식상 '신설'의 범위가 기존 건축물 전환을 포함하는지 확인되지 않으면 최종적으로 단정하기 어렵습니다.`

## 9. 회귀 평가

기존 E1~E38은 변경하지 않고 전부 유지한다.

### E39. Counterevidence — 별지서식 충돌형

실제 문제를 재현하는 고정 fixture를 추가한다. 외부 MCP 상태에 따라 평가결과가 달라지지 않도록 필요한 법적 전제를 프롬프트에 직접 제공한다.

예시 fixture:

```text
가상 법률 제10조는 "A센터를 설립하려는 자는 승인을 받아야 한다"고 규정하고 신축 제한은 두지 않는다.
가상 시행령은 A센터의 구조·입주·시설 요건만 규정한다.
가상 시행규칙 별지 신청서는 신청 유형을 "신설 / 증설"로만 구분한다.
기존 B공장 건축물이 A센터 구조·입주·시설 요건을 모두 충족하는 경우, 건축물을 새로 신축하지 않아도 A센터 설립승인을 받을 수 있는지 검토해줘.
```

PASS 조건:

- 법률에 신축 제한이 없다는 이유만으로 즉시 가능 결론을 내리지 않는다.
- 별지 신청서의 `신설 / 증설` 문구를 결론과 긴장관계에 있는 자료로 검토한다.
- `A센터 신설`과 `건축물 신축`이 동일 개념인지 문제 발생 지점으로 특정한다.
- 별지서식 문구만으로 즉시 불가라고 단정하지 않는다.
- 별지서식의 기능과 상위법 관계가 해결되지 않으면 조건부 결론으로 낮춘다.
- 기본 4단 H1을 유지한다.

### E40. 규정 부재 논증 Counterexample

다음 고정 fixture를 추가한다.

```text
가상 법률은 "A시설의 허가를 받아야 한다"고 규정하고 기존 시설의 전환을 금지하지 않는다.
가상 시행령에는 추가 제한이 없다.
가상 시행규칙 별지 신청서는 신청 유형을 "신규 설치 / 증설"로 표시한다.
기존 B시설의 용도만 A시설로 변경하려는 경우 허가 가능 여부를 검토해줘.
```

PASS 조건:

- `법률에 금지 규정이 없음 → 가능` 자동 추론을 하지 않는다.
- 별지서식과 법률 본문의 관계를 검토한다.
- 별지서식이 법률보다 상위 효력을 가진 것처럼 처리하지 않는다.
- 해결되지 않으면 조건부 결론을 사용한다.
- 모델이 존재하지 않는 반대근거를 추가로 만들어내지 않는다.

## 10. Expected Behavior 변경

`skills/law-interpretation-request/evals/expected-behavior.md`에 다음 계약을 추가한다.

- E39/E40은 Source Completeness와 Counterevidence 검증용이다.
- `명시적 제한 없음`이라는 부재 논증만으로 적극 결론을 확정하면 실패다.
- 발견된 하위법령·별표·별지서식은 법적 위계와 기능을 평가해야 한다.
- 하위 자료가 존재한다는 이유만으로 반대 결론을 자동 채택해도 실패다.
- 반대근거가 실제로 존재하지 않는 fixture에서 억지로 반대 논거를 생성하면 실패다.
- E1~E38의 기존 기대값은 그대로 유지한다.

## 17. 최종 설계 결정

v0.2.1은 별도 `adverse-authority-review.md` 또는 새로운 최상위 파이프라인 컴포넌트를 만들지 않는다.

Counterevidence 검증 책임은 다음처럼 배치한다.

- **Legal Issue Mapping:** 어떤 반대방향 자료가 쟁점 해결에 관련되는지 특정
- **Source Policy:** 관련 자료를 공식 출처에서 탐색하고 법적 위계·완전성을 확인
- **Logic Validation:** 발견된 중대한 반대근거가 해결되지 않은 확정 결론을 BLOCK
- **Rendering:** 내부 검증 결과를 별도 표로 노출하지 않고 자연스러운 법률논증과 조건부 결론에 반영

이 설계는 v0.2.0의 성공한 아키텍처를 유지하면서, 배포 후 발견된 `유리한 근거만으로 결론을 확정하는 source completeness gap`을 최소 범위로 보완한다.
