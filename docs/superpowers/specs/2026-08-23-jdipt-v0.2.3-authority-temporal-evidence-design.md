# JDIPT v0.2.3 Authority·Temporal·Evidence Contract Design

## 1. 목적

JDIPT v0.2.2는 `Legal Issue Mapping → Source Completeness / Counterevidence → Legal Interpretation → Logic Validation → Answer Rendering` 구조와 참조 별표·별지서식 resolution, URL provenance, 추상 fixture fail-closed 계약을 제공한다.

이번 변경은 기존 구조를 재작성하지 않고 다음 세 가지 남은 위험을 보완한다.

1. **적용 기준시점 오류**: 과거 허가·신청·처분·행위의 적법성 또는 법 적용을 묻는 질문에서 답변 시점의 현행법을 자동 적용하는 오류
2. **권위·법적 기능 혼동**: 법률, 하위법령, 행정규칙, 판례, 헌재결정, 법제처 해석례, 부처 질의회신을 단순 검색순위로 취급하는 오류
3. **출처 명제와 AI 추론 혼동**: 자료가 실제로 말한 내용과 여러 근거를 종합한 분석결론을 같은 종류의 주장처럼 표현하는 오류

목표는 새로운 데이터 플랫폼을 만드는 것이 아니라 **현재 Skill-first 구조 안에서 authority, applicable date, evidence provenance를 fail-closed 계약으로 고정하는 것**이다.

## 2. 범위

### 포함

- 질문의 `적용 기준시점`을 쟁점 매핑의 필수 조건으로 추가
- 현재 적용 질문과 과거 사실관계 질문의 법령 버전 선택을 분리
- 개정법 시행일·경과조치·변경허가/변경승인 등 신구법 연결 확인
- 자료별 `법적 권위`와 `법적 기능`을 구분
- 판례·법령해석례 사용 시 사실관계와 조문 버전의 동일성 확인
- `source claim`과 `analytical inference`를 구분하고 핵심 법적 명제에 provenance 요구
- deterministic pytest contract 추가
- E43~E48 행동 시나리오 명세 추가

## 3. 설계 원칙

### 3.1 기준시점 우선

법령 버전은 무조건 답변 시점의 현행법으로 선택하지 않는다.

내부 순서는 다음과 같다.

```text
질문에서 법적 효과가 발생한 시점 특정
→ 적용 기준시점 후보 확정
→ 그 시점에 유효한 법령 버전 확인
→ 개정법 시행일·경과조치 확인
→ 변경허가·변경승인 등 후속 행위가 있으면 별도 적용시점 검토
→ 현재법과 비교가 필요한 경우에만 현행법 병행 제시
```

현재 적용을 묻는 질문이고 별도 과거 시점이 없으면 현행법을 기본으로 한다. 반대로 허가일, 신청일, 처분일, 행위일 등 과거 시점이 결론을 좌우하면 해당 시점을 우선 검토한다. 기준시점이 불명확하고 결론이 달라질 수 있으면 임의로 채우지 않고 `확인 필요` 또는 조건부 결론으로 처리한다.

### 3.2 권위와 기능을 분리

자료는 검색 순위와 법적 효력을 혼동하지 않는다.

최소 구분:

- 헌법·법률
- 대통령령·총리령·부령
- 조례·규칙
- 행정규칙·고시·예규·훈령
- 대법원 판례
- 헌법재판소 결정
- 법제처 정부유권해석
- 소관부처 공식 질의회신·운영기준
- 기타 설명자료

각 자료에 대해 `무엇을 직접 규율하는가`, `상위 위임근거가 있는가`, `법원을 구속하는가`, `행정부 내 해석기준인가`, `해당 사실관계·조문 버전과 연결되는가`를 확인한다. 단순히 상위 자료라는 이유로 서로 다른 규율대상의 하위 규정을 배제하거나, 최신 자료라는 이유로 과거 사건에 소급 적용하지 않는다.

### 3.3 Source Claim과 Analytical Inference 분리

핵심 법적 명제는 현재 실행에서 확인한 자료에 추적 가능해야 한다.

- **Source Claim**: 법령 문언, 판례 판시, 법제처 해석례의 결론, 개정일·시행일 등 외부 자료의 내용에 관한 주장. 검증 가능한 공식 근거가 필요하다.
- **Analytical Inference**: 확인된 복수의 source claim과 사용자 사실을 연결하여 도출하는 해석·포섭·최종 판단. 모델이 생성할 수 있으나 source claim인 것처럼 표현해서는 안 된다.

따라서 `AI 문장마다 citation`을 요구하지 않는다. 대신 **결론을 지탱하는 material legal proposition에 provenance가 있어야 하고, 추론은 그 근거와 연결관계가 드러나야 한다.**

### 3.4 기존 Fail-closed 계약 유지

이번 변경은 v0.2.2의 다음 계약을 약화하지 않는다.

- 추상 fixture closed-world
- same-term conflict hard stop
- referenced annex/form resolution
- counterevidence
- URL provenance
- final rendering hard gate
- 기본 4단 Answer-first 출력

- 과거 허가·신청·처분과 후속 변경행위를 분리

### `references/interpretation-principles.md`

- 해석 시작 전 적용 법령 버전 확정 원칙 추가
- 판례·헌재·법제처·부처 자료의 권위와 기능 구분
- 동일/유사 선례 사용 시 조문 버전과 사실관계 비교

### `references/source-policy.md`

- 기존 `현행성`을 `적용 기준시점·현행성 Gate`로 확장
- `Authority / Legal Effect Gate` 추가
- `Claim-level Evidence Gate` 추가

### `tests/test_authority_temporal_evidence_contract.py`

정적 계약 테스트로 다음을 고정한다.

- 기준시점 marker 존재
- 경과조치 및 과거 사실관계 처리 marker 존재
- 법제처 해석례 비구속성/법적 기능 구분 marker 존재
- source claim / analytical inference 분리 marker 존재
- 기존 핵심 contract가 삭제되지 않았음

### `evals/v0.2.3-authority-temporal-evidence.md`

E43~E48 행동 시나리오를 정의한다.

- E43 과거 허가 시점 법령 선택
- E44 개정법·경과조치
- E45 법제처 해석례와 판례 권위 충돌
- E46 동일 판례의 구법/현행법 버전 차이
- E47 source claim과 분석추론 분리
- E48 기준시점 불명확 시 조건부 결론

이번 PR에서는 기존 full runner의 E1~E42 숫자 계약을 변경하지 않는다. E43~E48은 다음 live regression 확장 전에 deterministic contract와 수동/신규 컨텍스트 평가용 명세로 추가한다.

## 5. 검증

필수 deterministic 검증:

```bash
python scripts/validate_repo.py
python -m pytest -q
python -m py_compile scripts/regression_checks.py scripts/regression_oracles.py scripts/plugin_integrity.py scripts/run_release_gate.py
python scripts/run_release_gate.py
```

행동검증은 기존 E1~E42 회귀를 그대로 재실행하여 regression이 없는지 확인하고, E43~E48은 신규 컨텍스트에서 별도 실행하여 결과를 기록한다.

## 6. 성공 기준

- 과거 사건에 현행법을 무조건 적용하지 않는다.
- 기준시점이 결론을 좌우하지만 확인되지 않으면 조건부 결론으로 낮춘다.
- 법제처 해석례·부처 회신을 판례와 동일한 법적 구속력으로 표현하지 않는다.
- 과거 판례·해석례를 현재 조문에 적용할 때 조문 버전 차이를 확인한다.
- 외부 자료가 실제로 말한 내용과 모델의 종합 판단을 구분한다.
- 기존 E1~E42 및 v0.2.2 fail-closed 계약을 유지한다.
