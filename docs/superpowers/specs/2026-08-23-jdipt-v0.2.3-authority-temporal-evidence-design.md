# JDIPT v0.2.3 Authority·Temporal·Evidence Contract Design

> Evaluation execution details are defined by `2026-08-24-jdipt-eval-suite-consolidation-design.md`. The original six-case E43~E48 draft was consolidated into E43~E46 and the live suite is now manifest-driven.

## 1. 목적

JDIPT v0.2.2의 `Legal Issue Mapping → Source Completeness / Counterevidence → Legal Interpretation → Logic Validation → Answer Rendering` 구조를 유지하면서 다음 세 위험을 보완한다.

1. **적용 기준시점 오류**: 과거 허가·신청·처분·행위에 답변 시점의 현행법을 자동 적용하는 오류
2. **권위·법적 기능 혼동**: 법률, 하위법령, 판례, 헌재결정, 법제처 해석례, 부처 질의회신을 단순 검색순위로 취급하는 오류
3. **출처 명제와 AI 추론 혼동**: 자료가 실제로 말한 내용과 여러 근거를 종합한 분석결론을 같은 종류의 주장처럼 표현하는 오류

목표는 별도 데이터 플랫폼을 만드는 것이 아니라 현재 Skill-first 구조 안에서 authority, applicable date, evidence provenance를 fail-closed 계약으로 고정하는 것이다.

## 3. 설계 원칙

### 3.1 기준시점 우선

법령 버전은 무조건 답변 시점의 현행법으로 선택하지 않는다.

```text
법적 효과 발생시점 특정
→ 적용 기준시점 확정
→ 해당 시점 유효 법령 확인
→ 개정법 시행일·경과조치 확인
→ 변경허가·변경승인 등 후속 행위 별도 검토
→ 필요한 경우에만 현행법 비교
```

현재 적용을 묻고 별도 과거 시점이 없으면 현행법을 기본으로 한다. 과거 허가일·신청일·처분일·행위일이 결론을 좌우하면 그 시점을 우선한다. 기준시점이 불명확하고 결론이 달라질 수 있으면 `확인 필요` 또는 조건부 결론으로 처리한다.

### 3.2 권위와 기능 분리

자료는 검색 순위와 법적 효력을 혼동하지 않는다.

- 헌법·법률
- 대통령령·총리령·부령
- 조례·규칙
- 행정규칙·고시·예규·훈령
- 대법원 판례
- 헌법재판소 결정
- 법제처 정부유권해석
- 소관부처 공식 질의회신·운영기준
- 기타 설명자료

각 자료에 대해 규율대상, 위임근거, 해석주체, 법적 기능, 적용시점을 확인한다. 최신 자료라는 이유만으로 과거 사건에 적용하거나, 법제처 해석례를 법원 확정판결과 같은 구속력으로 취급하지 않는다.

### 3.3 Source Claim과 Analytical Inference 분리

- **Source Claim**: 법령 문언, 판례 판시, 법제처 해석례 결론, 개정일·시행일 등 외부 자료의 내용에 관한 주장. 현재 실행에서 확인한 근거가 필요하다.
- **Analytical Inference**: 확인된 source claim과 사용자 사실을 연결하여 도출하는 해석·포섭·최종 판단. 모델이 생성할 수 있으나 출처가 직접 말한 내용처럼 표현하지 않는다.

모든 문장에 citation을 강제하지 않는다. 결론을 지탱하는 material legal proposition에는 provenance가 있어야 하고, 추론은 근거와 연결관계가 드러나야 한다.

### 3.4 기존 Fail-closed 계약 유지

- 추상 fixture closed-world
- same-term conflict hard stop
- referenced annex/form resolution
- counterevidence
- URL provenance
- final rendering hard gate
- 기본 4단 Answer-first 출력

## 4. 평가 구조

v0.2.3 behavior는 다음 네 케이스로 통합한다.

| Case | 역할 |
|---|---|
| E43 | 최초 허가·개정법·경과조치·변경허가의 temporal lifecycle |
| E44 | material date 미확인 시 temporal fail-closed |
| E45 | 법제처/대법원 authority + precedent versioning |
| E46 | Source Claim / Analytical Inference 분리 |

실제 실행군은 `evals/suite-manifest.json`을 단일 원본으로 사용한다.

- Core: 14
- Full active: 26
- Legacy: 20
- Catalog: E1~E46

기존 E1~E42 fixture는 삭제하지 않는다. 중복도가 높은 케이스는 legacy catalog로 남기고 active 대표 시나리오와 deterministic oracle이 계약을 이어받는다.

## 6. 성공 기준

- 과거 사건에 현행법을 무조건 적용하지 않는다.
- 기준시점이 결론을 좌우하지만 확인되지 않으면 조건부로 낮춘다.
- 법제처 해석례·부처 회신을 판례와 동일한 법적 구속력으로 표현하지 않는다.
- 구법 판례·해석례를 현행 조문에 적용할 때 조문 버전 차이를 확인한다.
- 외부 자료가 실제로 말한 내용과 모델의 종합 판단을 구분한다.
- 기존 v0.2.2 fail-closed 계약을 유지한다.
- live Full 실행 수를 42건에서 26건으로 줄인다.
