# JDIPT v0.2.2 Regression Stabilization Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` (recommended) or `superpowers:executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** JDIPT v0.2.2의 반복적인 “실패 1건 → 패치 → 전체 재실행 → 다른 실패” 루프를 제거하고, 결정론적 로컬 게이트 → release-critical stability suite → E1–E42 전체 회귀 1회 → real-law smoke의 고정된 release pipeline을 구축한다.

**Architecture:** 기존 `run_jdipt_full_regression_v4.py`의 CLI와 E1–E42 계약은 유지한다. 판정 로직을 순수 함수 모듈로 분리하고, 알려진 회귀를 재현하는 로컬 fixture/unit test, case별 deterministic contract oracle, 설치본 무결성 검사, release gate orchestration을 추가한다. v0.2.2 제품 프롬프트/Skill 계약은 RC 이후 동결하고, 전체 회귀는 모든 사전 게이트가 통과한 경우에만 한 번 실행한다.

**Tech Stack:** Python 3.x stdlib, pytest, PowerShell, Codex CLI, npm, Git.

**Spec:** 현재 대화에서 승인된 “계약·runner·semantic oracle을 함께 재정비하는 C안”.

## Global Constraints

- `allow_implicit_invocation: false`는 변경하지 않는다.
- Plugin ID/Version은 `jdipt@jdipt-local`, `0.2.2`를 유지한다.
- E1–E42의 번호와 핵심 Expected 의미를 release stabilization 중 임의 변경하지 않는다.
- E2/E3는 `SKIP_SPECIAL_FORMAT`이 정상이며 전체 H1 목표는 `40/42`다.
- Windows PowerShell에서 Markdown을 읽을 때 `-Encoding UTF8` 계약을 유지한다.
- 추상 fixture closed-world, same-term conflict Hard Stop, referenced annex/form resolution BLOCK, URL provenance/encoding 계약을 완화하지 않는다.
- 제품 동작을 PASS시키기 위해 evaluator를 약화하지 않는다.
- evaluator를 PASS시키기 위해 제품 응답을 특정 문자열 하나에 과적합하지 않는다.
- 새 외부 Python dependency를 추가하지 않는다. Oracle 데이터는 JSON을 사용한다.
- GitHub Actions를 release blocker로 사용하지 않는다. 로컬 수동 gate를 공식 검증 근거로 사용한다.
- `regression-results/`, 임시 `apply_*.py`, 임시 ZIP은 기본적으로 커밋하지 않는다.
- 전체 E1–E42 실행 후 제품 파일이 변경되면 그 full run은 무효다.
- full run 실패 시 즉시 개별 패치하지 않는다. 모든 실패를 `PRODUCT / RUNNER / ENVIRONMENT / ORACLE`로 분류한 뒤 consolidated patch 1회만 허용한다.
- remote push는 최종 release gate 완료 전 금지한다.
