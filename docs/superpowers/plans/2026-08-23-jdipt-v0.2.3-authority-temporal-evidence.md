# JDIPT v0.2.3 Authority·Temporal·Evidence Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** JDIPT가 법령해석 시 적용 기준시점, 자료 권위·법적 효력, 출처 명제와 분석추론을 명확히 구분하도록 기존 v0.2.2 계약을 확장한다.

**Architecture:** 기존 `Legal Issue Mapping → Source Completeness / Counterevidence → Legal Interpretation → Logic Validation → Answer Rendering` 흐름은 유지한다. 새 기능은 별도 데이터 플랫폼을 만들지 않고 `legal-issue-mapping.md`, `interpretation-principles.md`, `source-policy.md`에 fail-closed 규칙을 추가하고, deterministic pytest와 E43~E48 행동 시나리오로 계약을 고정한다.

**Tech Stack:** Markdown Skill/reference contracts, Python 3 deterministic validation/pytest, existing JDIPT regression framework, GitHub/Codex Plugin packaging.

**Spec:** `docs/superpowers/specs/2026-08-23-jdipt-v0.2.3-authority-temporal-evidence-design.md`

## Global Constraints

- `law-interpretation-request`는 explicit-only Skill로 유지하고 `allow_implicit_invocation: false`를 변경하지 않는다.
- 기본 사용자 출력은 정확한 H1 4단 구조를 유지한다.
- 법제처 제출용 H1 1~3 계약을 변경하지 않는다.
- `korean-law-mcp` 4.12.1을 유지하고 업스트림 내부 API에 직접 결합하지 않는다.
- v0.2.2의 Abstract Fixture, Counterevidence, Referenced Source Resolution, URL Provenance, Final Rendering Hard Gate를 약화하지 않는다.
- 이번 PR에서는 package/plugin version을 올리지 않고 release 문서에 v0.2.3 PASS를 선언하지 않는다.
- 이번 PR에서는 machine oracle/full regression의 E01~E42 산술을 변경하지 않는다. E43~E48은 신규 동작 명세 및 deterministic contract로 추가한다.

### Task 4: Source Policy에 Temporal·Authority·Claim-level Evidence Gate 추가

**Files:**
- Modify: `skills/law-interpretation-request/references/source-policy.md`

**Interfaces:**
- Consumes: 공식 원천, Legal Issue Mapping의 적용 기준시점
- Produces: 적용시점에 맞는 자료 선택, 권위/효력 평가, source claim과 inference provenance

- [ ] **Step 1: 기존 `현행성`을 `적용 기준시점·현행성 Gate`로 확장한다.**

핵심 규칙:

```markdown
- 현재 적용 질문은 현행법을 기본으로 한다.
- 과거 허가·신청·처분·행위의 법적 효과를 묻는 경우에는 해당 기준시점에 유효한 법령을 먼저 확인한다.
- 후속 변경허가·변경승인이 있으면 그 행위의 기준시점을 별도로 검토한다.
- 개정법의 시행일과 부칙 경과조치를 실제로 확인한다.
- 기준시점이 결론을 좌우하지만 확인되지 않으면 확정 결론을 내리지 않는다.
```

- [ ] **Step 2: `Authority / Legal Effect Gate`를 추가한다.**

검색 우선순위와 법적 효력을 분리하고 최소한 법률/하위법령/자치법규/행정규칙/대법원/헌재/법제처/소관부처 자료를 구분한다.

- [ ] **Step 3: `Claim-level Evidence Gate`를 추가한다.**

핵심 규칙:

```markdown
- Source Claim: 외부 자료의 문언·판시·해석결론·시행일 등에 관한 주장으로 현재 실행에서 검증 가능한 근거가 필요하다.
- Analytical Inference: 확인된 source claim과 사용자 사실을 연결해 도출하는 분석·포섭·최종 판단으로 생성할 수 있으나 출처가 직접 말한 내용처럼 표현하지 않는다.
- 모든 문장에 인용을 강제하지 않는다. 결론을 지탱하는 material legal proposition과 출처 특정 주장에는 provenance가 있어야 한다.
- 결정적 전제의 provenance가 없으면 확정 결론을 낮춘다.
```

- [ ] **Step 4: 기존 URL/Counterevidence/Referenced Source Gate가 그대로 남아 있는지 확인한다.**

- [ ] **Step 5: Task 1의 source-policy 테스트 두 개를 실행한다.**
