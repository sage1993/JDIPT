# JDIPT v0.2 Legal Analysis and Output Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** JDIPT의 기본 법률검토 동작을 `법적 쟁점 매핑 → 법령해석 → 논리검증 → 4단 Answer-first 출력` 구조로 전환하고, 단일 쟁점의 논증을 과도한 소제목 없이 연속적으로 작성하도록 한다.

**Architecture:** 기존 Skill-first 구조와 Korean Law MCP 경계는 유지한다. `references/legal-issue-mapping.md`를 새 내부 Gate 계약으로 추가하고, 기존 `interpretation-principles.md`와 `logic-validation.md` 앞뒤 책임을 분리한다. 사용자 출력은 기본 1~6 구조를 폐기하고 `질의요지 → 검토결론 → 검토이유 → 관련 법령 및 자료` 4단 구조로 마이그레이션하되, 법제처 제출용 1~3 구조는 그대로 유지한다.

**Tech Stack:** Markdown Skill/Reference/Eval 문서, Python 3.11+ 정적 validator, Node.js >=20.19.0, Codex Plugin manifest, `korean-law-mcp` 4.12.1.

**Spec:** `docs/superpowers/specs/2026-08-21-jdipt-v0.2-legal-analysis-output-design.md`

## Global Constraints

- 기본 법률검토형 H1은 정확히 `# 1. 질의요지`, `# 2. 검토결론`, `# 3. 검토이유`, `# 4. 관련 법령 및 자료` 순서로 사용한다.
- 상세 검토이유보다 검토결론을 먼저 제시한다.
- 단일 쟁점에서는 `법적 정의`, `적용 규정`, `사안 적용`, `문제 발생 지점`, `해석`을 각각 별도 소제목으로 기계적으로 분리하지 않는다.
- `# 3. 검토이유`의 하위 소제목은 서로 독립적으로 판단 가능한 복수 쟁점이 있을 때만 사용한다.
- Legal Issue Mapping은 내부 절차이며 그 내부 라벨·중간표를 기본 사용자 출력에 노출하지 않는다.
- 법제처 제출용 1~3 구조는 변경하지 않는다.
- `references/logic-validation.md`의 점수체계, BLOCK, 추상 입력 보존, 비노출 계약은 변경하지 않는다.
- `korean-law-mcp` 버전은 `4.12.1`로 유지하고 MCP 도구 인터페이스를 변경하지 않는다.
- JDIPT Plugin 버전은 `0.2.0`으로 올린다.
- 확인되지 않은 사실·판례·해석례·URL을 생성하지 않는다.
- 모든 사용자용 최종 출력은 Markdown을 유지한다.
