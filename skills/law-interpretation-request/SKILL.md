# 법령해석요청 작성

대한민국 법령의 객관적 의미와 적용범위를 체계적으로 검토하고, 실무자가 제출·검토하기 쉬운 법령해석요청 문안을 작성한다. 기본 언어는 한국어이며 공적·간결한 법률검토 문체를 사용한다.

## 우선순위

1. **사용자의 최신 명시 지시**를 최우선으로 따른다.
2. 업로드된 기준 문서가 있으면 구조·항목·표현·논리 전개·제목·질의 형식·첨부 배열을 먼저 분석하고 최대한 유사하게 반영한다. 내용은 새 사실관계와 새 쟁점에 맞게 재구성한다.
3. 다음으로 이 스킬의 기본 형식과 `references/`를 적용한다.

## 작업 순서

1. 요청 목적과 제출/사용 맥락을 1~2문장으로 특정한다.
2. 먼저 `references/eligibility-checklist.md`로 법령해석 대상 적합성을 점검한다.
3. 작성에 필수적인 정보가 없으면 필요한 것만 3~7개 질문한다. 이미 충분한 정보가 있으면 질문하지 않는다.
4. 법령·판례·해석례를 인용해야 하면 `references/source-policy.md`에 따라 **공식자료와 현행성을 우선 확인**한다.
5. Korean Law MCP가 사용 가능하면 아래 `MCP 조사 절차`를 따른다.
6. `references/interpretation-principles.md`와 `references/case-patterns.md`를 사용해 문언 → 정의/참조 → 체계 → 목적 → 연혁 → 다른 법령 → 판례·해석례 순으로 필요한 단계만 검토한다.
7. 사실관계와 법적 판단을 분리하고, 갑설·을설 또는 내부 검토 결론을 뒷받침하는 **법적 논증 초안**을 먼저 만든다.
8. 최종 문안 작성 전에 **반드시** `references/logic-validation.md`에 따라 내부 논리검증을 수행한다. 논증 분해 → 기호화/표준형 변환 → 전제 검토 → 추론 타당성 → 오류·전제 누락·반례 → 점수화 → 수정·재검증 순서를 지킨다.
9. 논리검증의 `BLOCK` 항목이 있으면 논증을 수정하고 다시 검증한다. 누락 전제를 확인할 수 없으면 임의로 보충하지 말고 결론을 조건부로 낮추거나 `확인 필요`로 표시한다.
10. 논리검증을 통과하거나 미해결 사항이 적절히 조건부 처리된 뒤 출처·현행성·인용을 최종 검증한다.
11. 결과를 해당 출력 모드로 작성하고 제출 전 주의문을 붙인다.

## MCP 조사 절차

Korean Law MCP가 연결되어 있으면 일반 웹 검색보다 공식 법령 데이터 조회를 우선한다.

1. `search_law`로 정확한 법령명과 식별자를 확인한다.
2. 최종 인용할 조문은 반드시 `get_law_text`로 본문을 재확인한다.
3. 관련 판례·법령해석례 등은 `search_decisions`로 찾고, 채택할 자료는 `get_decision_text`로 본문을 확인한다.
4. 연혁·과거법·조문관계·세부자료가 필요하지만 직접 도구가 보이지 않으면 `discover_tools`로 찾고 `execute_tool`을 사용한다.
5. 최종 문안의 인용문과 법령명이 확정되면 `legal_analysis`의 인용 검증 기능을 우선 고려한다.
6. MCP 오류·일시 장애·부분 결과를 `자료 없음`으로 단정하지 않는다. 확인 실패와 부존재를 구분한다.

MCP가 연결되어 있지 않으면 `references/source-policy.md`의 공식 사이트 우선순위에 따라 조사한다.

## 내부 논리검증 Gate

최종 답변을 생성하기 전에 `references/logic-validation.md`를 **필수 절차**로 사용한다.

- 원문 또는 확인된 법적 근거에 없는 전제를 사실처럼 추가하지 않는다.
- 삼단논법, 전건 긍정, 후건 부정, 이중부정, 선언 명제를 우선 판별하되 정확히 맞지 않으면 `비정형 자연어 추론`으로 분류한다.
- 전건 부정, 후건 긍정, 거짓 양자택일, 순환논증, 개념의 미끄러짐, 모순, 성급한 일반화, 근거 부족, 전제 누락을 탐지한다.
- 필요조건과 충분조건, 인과관계와 상관관계를 혼동하지 않는지 확인한다.
- 형식적 타당성과 건전성 상태를 분리한다. 외부 확인이 필요한 전제는 `사실성 미확인`으로 처리하며 그 자체만으로 논리 점수를 감점하지 않는다.
- 법제처 모드에서는 **갑설과 을설을 각각 독립 검증한 뒤 상호 비교**한다.
- 검증 결과의 기호화, 점수표, 반례 탐색 과정, 내부 수정 메모는 사용자가 명시적으로 요구하지 않는 한 최종 답변에 노출하지 않는다.
- 논리검증은 체크리스트로 끝내지 않고, 발견한 문제를 실제 논증에 반영한 뒤 재검증해야 한다.

## 법제처 법령해석요청서 모드

사용자가 법제처 제출용, 법령해석요청서, 질의요지·갑설·을설 작성을 요청하면 `references/request-format.md`를 따른다.

**최종 문안의 본문 번호는 반드시 1~3만 사용한다. 4~8 항목을 생성하지 않는다.**

1. 질의요지
2. 해석대상 법령조문 및 관련 법령
   - 가. 해석대상 법령조문
   - 나. 관련 법령
3. 대립되는 의견 및 이유
   - 가. 갑설
   - 나. 을설

갑설·을설을 기계적으로 50:50으로 만들지 않는다. 각 설의 법적 근거 강도를 사실대로 드러내되, 회신기관이 판단할 수 있도록 양쪽 논거를 가능한 범위에서 완결된 형태로 제시한다.

## 부적합·모호 질의

법령해석 대상으로 부적합하거나 자료 부족 때문에 정상 초안 제출이 곤란하면 **설명 우선 병행형**으로 쓴다.

1. 부적합 사유와 보완 포인트
2. `참고용 원문형 초안 — 제출 적합성 낮음`
3. `권고 보정 초안 — 제출 권고`

구체적 사실인정·기존 처분의 위법성 판단을 직접 구하는 질문은 가능한 경우 **법규범의 객관적 의미·적용범위**를 묻는 형식으로 보정한다.

## 기타 출력 모드

법제처 제출용이 아니면 사용자가 요구한 공문, 민원, 기관 제출, 내부 검토 메모 형식을 따른다. 별도 형식 지시가 없으면 `references/request-format.md`의 내부 법률검토형을 사용한다.

## 인용과 링크

자료를 인용한 모든 핵심 주장에는 각주형 링크를 붙인다. MCP나 공식 사이트에서 확인한 실제 URL이 있으면 그것을 사용한다. 정확한 URL을 확인하지 못한 경우 링크를 추정하지 말고 `[공식 링크 확인 필요]`라고 표시한다. Wikipedia 등 2차 자료는 방법론 참고에만 쓰고 법적 결론의 주된 근거로 삼지 않는다.

## 제출 전 주의문

모든 결과 말미에 번호 없는 `※ 제출 전 확인`을 붙여 다음을 짧게 점검한다.

- 법률자문 확정 의견이 아니라 제출용 초안임
- 사실관계, 해석대상 조문, 최신 개정 여부 재확인
- 법제처 요청이면 소관 중앙행정기관 의견 첨부 필요 여부 확인
- 입증자료·관련 처분서·검토자료 등 첨부 누락 확인
- 구체적 사실판단이나 이미 이루어진 처분의 위법성 판단을 직접 구하는 형식은 법제처 해석 대상에서 제외될 수 있음

상세 원칙과 사례는 필요한 경우에만 `references/`에서 읽는다.
