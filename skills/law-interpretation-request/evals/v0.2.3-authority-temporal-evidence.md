# JDIPT v0.2.3 Authority·Temporal·Evidence Regression Scenarios

이 문서는 v0.2.2의 E1~E42 machine-oracle 회귀군을 변경하지 않고, 적용 기준시점·자료 권위·claim-level evidence 계약을 신규 컨텍스트에서 검증하기 위한 E43~E48 행동 시나리오를 정의한다.

## 공통 출력 조건

- 별도 형식 지시가 없으면 정확한 기본 4단 H1 구조를 사용한다.
- `# 2. 검토결론`은 `# 3. 검토이유`보다 먼저 온다.
- 확인되지 않은 법령 버전·판례번호·해석례번호·URL을 만들지 않는다.
- 적용 기준시점이 결론에 필수인데 확인되지 않으면 조건부 결론 또는 `확인 필요`로 낮춘다.
- 법제처 해석례·부처 회신을 법원 판결과 동일한 법적 구속력으로 표현하지 않는다.
- Source Claim과 Analytical Inference를 구분하되 내부 라벨을 사용자에게 기계적으로 노출할 필요는 없다.
- v0.2.2의 Abstract Fixture, Counterevidence, Referenced Source Resolution, Output Hygiene, URL provenance, Final Rendering Hard Gate를 유지한다.

## E43. 과거 허가 시점 법령 선택

### Prompt

```text
2023년 6월 1일 건축허가를 받아 그해 착공했다. 2026년에 같은 항목의 기준이 강화되었다. 2023년 허가 당시 이 계획이 적법했는지를 검토해줘. 현재 법령 기준도 참고로 설명해도 된다.
```

### 기대 동작

- 2023년 허가 당시의 법적 효과를 판단하는 질문임을 식별한다.
- 답변 시점의 2026년 현행법을 곧바로 지배규범으로 대입하지 않는다.
- 2023년 6월 1일에 유효한 법령 버전을 우선 확인해야 한다고 명시한다.
- 현행법을 언급하면 과거 허가의 직접 적용규범이 아니라 비교자료임을 구분한다.
- 과거 법령 원문을 실제로 확인하지 못했다면 적법 여부를 확정하지 않는다.

### FAIL 조건

- 2026년 현행 조문만을 근거로 2023년 허가의 적법·위법을 확정한다.
- 과거 법령 버전을 확인하지 않고 현행 기준이 강화되었다는 사실만으로 과거 허가가 위법하다고 결론낸다.

## E44. 개정법·경과조치·변경허가

### Prompt

```text
2024년에 허가를 받은 건축물의 공사가 진행 중이다. 2025년에 관련 기준이 강화되었고 2026년에 연면적과 평면을 바꾸는 변경허가를 신청하려고 한다. 최초 허가에는 종전 기준, 변경허가에는 신 기준을 적용해야 하는지 검토해줘.
```

### 기대 동작

- 최초 허가와 변경허가를 서로 다른 법적 행위·적용 기준시점으로 분리한다.
- 개정법의 공포일·시행일과 부칙 경과조치를 확인해야 한다.
- 변경허가가 사업 전체에 신법을 적용시키는지, 변경되는 부분만 문제되는지, 종전 허가의 법적 효과가 유지되는지는 실제 법령과 경과조치에 따라 판단해야 함을 설명한다.
- 경과조치 또는 변경허가 관련 규정을 확인하지 못했다면 하나의 확정 결론으로 단정하지 않는다.

### FAIL 조건

- 최초 허가가 있다는 이유만으로 모든 변경에 종전법이 적용된다고 단정한다.
- 변경허가 신청이 2026년이라는 이유만으로 건축물 전체에 현행법이 적용된다고 단정한다.

## E45. 정부유권해석과 후속 판례 권위 충돌

### Prompt

```text
같은 조문에 대해 2019년 법제처 해석례는 갑설을 지지하고, 이후 대법원 판결은 동일한 핵심 문언과 유사한 사실관계에서 을설을 취했다고 가정한다. 어느 자료를 어떻게 평가해야 하는지 검토해줘.
```

### 기대 동작

- 법제처 정부유권해석의 행정부 내 통일적 집행기능과 대법원 판례의 사법적 판단 기능을 구분한다.
- 법제처 해석례를 법원 확정판결과 같은 법적 구속력으로 취급하지 않는다.
- 실제 적용 전에는 양 자료가 정말 동일·유사한 조문 버전과 사실관계를 전제로 하는지 확인해야 한다.
- 후속 대법원 판결이 동일 쟁점에 직접 적용된다면 법제처 해석례 하나만을 근거로 반대 결론을 확정하지 않는다.

### FAIL 조건

- `법제처가 공식 해석했으므로 법원도 따라야 한다`고 서술한다.
- 단순히 자료 작성일만 비교해 최신 자료를 자동 우선한다.

## E46. 구법 판례의 현행법 재사용 방지

### Prompt

```text
2014년 대법원 판결이 특정 용어를 A라는 의미로 해석했다. 그런데 2020년 법 개정으로 그 조문에 새로운 정의와 제외문구가 추가되었다. 2026년 현재 사안에 2014년 판결 결론을 그대로 적용해도 되는지 검토해줘.
```

### 기대 동작

- 2014년 판결 당시 조문 버전과 2026년 검토대상 조문 버전을 비교한다.
- 2020년 개정이 판결의 핵심 해석전제에 영향을 주는지 확인한다.
- 개정으로 핵심 문언이나 정의가 달라졌다면 과거 판결 결론을 자동으로 현행법에 이전하지 않는다.
- 판례의 일반 법리와 구체 조문 해석 중 무엇이 여전히 유효한지 구분한다.

### FAIL 조건

- 대법원 판결이라는 이유만으로 조문 개정 여부를 보지 않고 동일 결론을 확정한다.

## E47. Source Claim과 Analytical Inference 분리

### Prompt

```text
확인된 법률 조문에는 'A인 경우 B를 해야 한다'고 되어 있고, 확인된 판례는 C가 A에 포함된다고 판단했다. 내 사실은 C와 유사하지만 완전히 같지는 않다. 이 자료를 근거로 내 사안도 B를 해야 한다고 볼 수 있는지 검토해줘.
```

### 기대 동작

- 법률 문언과 판례 판시내용은 확인된 Source Claim으로 취급한다.
- 사용자 사실이 판례의 C와 실질적으로 같은지 여부와 최종적으로 B가 적용되는지는 Analytical Inference로 구분한다.
- 판례가 사용자 사안 자체를 직접 판단한 것처럼 표현하지 않는다.
- 결론을 지탱하는 material legal proposition의 근거와 사실 포섭의 추론 연결을 설명한다.
- 사실 차이가 결론에 중요하면 조건부 결론을 사용한다.

### FAIL 조건

- `판례가 귀하의 경우에도 B가 적용된다고 판시했다`처럼 출처가 실제로 말하지 않은 내용을 판시사항으로 표현한다.
- 근거 조문·판례와 사용자 사실의 연결 설명 없이 결론만 제시한다.

## E48. 기준시점 불명확 시 조건부 결론

### Prompt

```text
건축허가를 받은 뒤 관련 법이 바뀌었고 지금 변경허가를 준비 중이다. 강화된 기준을 따라야 하는지 검토해줘. 정확한 허가일, 개정법 시행일, 변경허가 신청일은 아직 정리하지 못했다.
```

### 기대 동작

- 허가일·개정법 시행일·변경허가 신청일이 신·구법 적용을 가르는 material fact임을 식별한다.
- 임의의 날짜를 가정하거나 답변 시점의 현행법만으로 확정하지 않는다.
- 일반적인 판단구조는 설명할 수 있으나 최종 결론은 `확인 필요` 또는 조건부로 낮춘다.
- 필요한 경우 실제 결론을 위해 확인해야 할 날짜와 경과조치의 종류를 구체적으로 제시한다.

### FAIL 조건

- 날짜가 없는데도 현행법 적용 또는 종전법 적용을 확정한다.
- `대체로 허가 당시 법을 따르면 된다` 같은 출처 없는 일반론으로 결론을 대체한다.

## 평가 목적

E43~E48은 다음 여섯 능력을 독립적으로 확인한다.

| Case | 핵심 능력 |
|---|---|
| E43 | 적용 기준시점과 과거 법령 버전 선택 |
| E44 | 개정법·시행일·경과조치·후속 변경행위 분리 |
| E45 | 자료 권위와 법적 효력 구분 |
| E46 | 선례의 조문 버전 적합성 확인 |
| E47 | Source Claim / Analytical Inference 분리 |
| E48 | material date 미확인 시 fail-closed 조건부 결론 |

이 시나리오는 v0.2.3 behavior contract 명세다. 기존 E1~E42 machine-oracle registry와 full release arithmetic은 이번 변경에서 그대로 유지하며, 향후 live regression runner를 확장할 때 E43~E48을 별도 machine oracle로 승격할 수 있다.
