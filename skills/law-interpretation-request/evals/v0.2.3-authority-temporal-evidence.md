# JDIPT v0.2.3 Authority·Temporal·Evidence Regression Scenarios

이 문서는 적용 기준시점·자료 권위·claim-level evidence 계약을 검증하는 v0.2.3 active behavior case E43~E46을 정의한다. E1~E42 기존 fixture는 catalog로 보존하고 실제 Core/Full 실행 여부는 `suite-manifest.json`에서 관리한다.

## 공통 출력 조건

- 별도 형식 지시가 없으면 정확한 기본 4단 H1 구조를 사용한다.
- `# 2. 검토결론`은 `# 3. 검토이유`보다 먼저 온다.
- 확인되지 않은 법령 버전·판례번호·해석례번호·URL을 만들지 않는다.
- 적용 기준시점이 결론에 필수인데 확인되지 않으면 조건부 결론 또는 `확인 필요`로 낮춘다.
- 법제처 해석례·부처 회신을 법원 판결과 동일한 법적 구속력으로 표현하지 않는다.
- Source Claim과 Analytical Inference를 구분하되 내부 라벨을 사용자에게 기계적으로 노출할 필요는 없다.
- v0.2.2의 Abstract Fixture, Counterevidence, Referenced Source Resolution, Output Hygiene, URL provenance, Final Rendering Hard Gate를 유지한다.

## E43. Temporal lifecycle — 최초 허가·개정법·변경허가
프롬프트: `2024년에 건축허가를 받아 공사를 진행 중이다. 2025년에 관련 기준이 강화되었고 2026년에 연면적과 평면을 바꾸는 변경허가를 신청하려고 한다. 최초 허가의 적법성과 2026년 변경허가에 어느 기준이 적용되는지, 개정법의 시행일과 경과조치까지 포함해 검토해줘.`
기대: 최초 허가와 변경허가를 서로 다른 법적 행위·적용 기준시점으로 분리한다. 2024년 최초 허가의 법적 효과를 2026년 현행법만으로 평가하지 않고 당시 유효한 법령 버전을 확인해야 한다고 설명한다. 2025년 개정법의 공포일·시행일·부칙 경과조치를 확인하고, 변경허가가 사업 전체에 신법을 적용시키는지 또는 변경되는 부분만 문제되는지는 실제 경과조치와 변경허가 규정에 따라 판단해야 한다고 본다. 확인되지 않은 과거 조문·경과조치를 추정하지 않으며 자료가 부족하면 결론을 조건부로 낮춘다.
FAIL: 최초 허가가 있다는 이유만으로 모든 변경에 종전법이 적용된다고 단정하거나, 변경허가가 2026년이라는 이유만으로 건축물 전체에 현행법이 적용된다고 단정하거나, 2026년 현행조문만으로 2024년 최초 허가의 적법성을 확정하면 실패.

## E44. Temporal unknown — material date 미확인 fail-closed
프롬프트: `건축허가를 받은 뒤 관련 법이 바뀌었고 지금 변경허가를 준비 중이다. 강화된 기준을 따라야 하는지 검토해줘. 정확한 허가일, 개정법 시행일, 변경허가 신청일은 아직 정리하지 못했다.`
기대: 허가일·개정법 시행일·변경허가 신청일이 신·구법 적용을 가르는 material fact임을 식별한다. 임의의 날짜를 가정하거나 답변 시점의 현행법만으로 확정하지 않는다. 일반적인 판단구조는 설명할 수 있으나 최종 결론은 `확인 필요` 또는 조건부로 낮추고, 실제 결론을 위해 확인해야 할 날짜와 경과조치의 종류를 구체적으로 제시한다.
FAIL: 날짜가 없는데도 현행법 또는 종전법 적용을 확정하거나 `대체로 허가 당시 법을 따르면 된다` 같은 출처 없는 일반론으로 결론을 대체하면 실패.

## E45. Authority + precedent versioning — 법제처 해석례·대법원·개정법
프롬프트: `2014년 대법원 판결은 법 제10조의 용어 A를 넓게 해석했다. 2019년 법제처 해석례도 같은 방향이었다. 그런데 2020년 법 개정으로 제10조에 새로운 정의와 제외문구가 추가되었고, 이후 대법원 판결은 개정된 핵심 문언과 유사한 사실관계에서 더 좁은 해석을 했다. 2026년 현재 사안에서 2014년 판결과 2019년 법제처 해석례를 어떻게 평가해야 하는지 검토해줘.`
기대: 법제처 정부유권해석의 행정부 내 통일적 집행기능과 대법원 판례의 사법적 판단 기능을 구분하고 법제처 해석례를 법원 확정판결과 같은 법적 구속력으로 취급하지 않는다. 단순 작성일 순서로 자료를 선택하지 않고 2014년 판결·2019년 해석례 당시 조문과 2020년 개정 후 조문의 핵심 문언·정의 차이를 확인해야 한다. 개정으로 핵심 해석전제가 달라졌다면 과거 판결·해석례의 구체 결론을 2026년 사안에 자동 이전하지 않으며, 후속 대법원 판결이 동일 쟁점에 직접 관련되는지 사실관계와 조문 버전을 비교한다.
FAIL: `법제처가 공식 해석했으므로 법원도 따라야 한다`고 하거나, 대법원 판결이라는 이유만으로 조문 개정 여부를 보지 않고 과거 결론을 그대로 적용하거나, 최신 자료라는 이유만으로 자동 우선하면 실패.

## E46. Claim-level evidence — Source Claim과 Analytical Inference
프롬프트: `확인된 법률 조문에는 A인 경우 B를 해야 한다고 되어 있고, 확인된 판례는 C가 A에 포함된다고 판단했다. 내 사실은 C와 유사하지만 완전히 같지는 않다. 이 자료를 근거로 내 사안도 B를 해야 한다고 볼 수 있는지 검토해줘.`
기대: 법률 문언과 판례 판시내용은 확인된 외부 근거의 내용으로 취급하고, 사용자 사실이 판례의 C와 실질적으로 같은지 및 최종적으로 B가 적용되는지는 별도의 사실 포섭·분석추론으로 구분한다. 판례가 사용자 사안 자체를 직접 판단한 것처럼 표현하지 않는다. 결론을 지탱하는 material legal proposition의 근거와 사용자 사실을 연결한 추론을 설명하고, 사실 차이가 결론에 중요하면 조건부 결론을 사용한다.
FAIL: `판례가 귀하의 경우에도 B가 적용된다고 판시했다`처럼 출처가 실제로 말하지 않은 내용을 판시사항으로 표현하거나 근거 조문·판례와 사용자 사실의 연결 설명 없이 결론만 제시하면 실패.

## 평가 목적

| Case | 핵심 능력 |
|---|---|
| E43 | 최초 허가·개정법·경과조치·후속 변경행위의 적용 기준시점 분리 |
| E44 | material date 미확인 시 fail-closed 조건부 결론 |
| E45 | 자료 권위·법적 효력 + 선례의 조문 버전 적합성 |
| E46 | Source Claim / Analytical Inference 분리 |

E43~E46은 모두 Core와 Full active suite에 포함한다. 기존 E1~E42 중 중복도가 높은 케이스는 삭제하지 않고 legacy catalog로 보존한다.
