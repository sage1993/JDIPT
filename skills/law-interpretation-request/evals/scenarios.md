# Skill evaluation scenarios

E1~E25와 E27~E38은 새 컨텍스트에서 `$law-interpretation-request`를 명시적으로 호출해 Skill 자체의 행동을 검증한다. E26은 JDIPT Plugin을 설치한 새 컨텍스트에서 Skill명이나 `@jdipt`를 쓰지 않고 자동 적용 여부를 검증한다.

## E10~E20 공통 출력 조건

E10~E20은 논리검증 Gate의 **행동 결과**를 검증한다. 사용자가 별도로 논리감사·형식논리 설명을 요청하지 않은 한 최종 사용자 출력에는 내부 검증 흔적을 노출하지 않는다.

- `P`, `Q`, `R`, `A → B`, `¬A`, `∴ B` 같은 내부 기호화·논리식을 기본 출력에 표시하지 않는다.
- `전건 부정`, `후건 긍정`, `거짓 양자택일` 같은 내부 오류분류명, 내부 점수, 반례표, 수정표를 기본 출력에 표시하지 않는다.
- 발견한 오류는 일반 법률검토 문장으로 고쳐 최종 논증에 반영한다.
- 사용자가 A/B/P/Q 같은 추상 기호만 제시한 논리 테스트에서는 특정 법령·조문·판례·법제처 해석례·사실관계를 임의로 대응시키거나 만들어내지 않는다.

## E1. 법제처 출력 구조 강제
프롬프트: `법제처 법령해석요청서로 작성해. 법령과 사실관계는 충분히 제공함.`
기대: 명시적 법제처 요청이므로 본문 번호는 1~3만 존재. 4~8 번호 없음. 말미에는 번호 없는 제출 전 확인만 존재.

## E2. 구체적 사실판단형 보정
프롬프트: `내 건물이 법 제10조의 시설에 해당하는지 법제처에 물어보고 싶어.`
기대: 적합성 문제 설명 → 제출 적합성 낮은 원문형 → 법 제10조의 객관적 의미·포함범위를 묻는 보정안.

## E3. 처분 위법성 직접 질의
프롬프트: `구청의 불허가 처분이 위법한지 법제처에 질의서 써줘.`
기대: 처분 위법성 직접 판단은 부적합 가능성이 있다고 설명하고, 해당 처분 근거조항의 적용범위·요건 해석으로 재구성.

## E4. 명확한 문언
프롬프트: 명시적 제외 문구가 있는 조문 A/B를 주고 B 적용 가능 여부 질문.
기대: 명확한 문언을 우선하고 불필요한 목적론을 과도하게 동원하지 않음.

## E5. 예외·특례 중첩
프롬프트: 서로 다른 두 완화특례를 동시에 중첩 적용할 수 있는지 질문.
기대: 원칙 규정 → 각 특례 → 중첩 허용 명문 존재 여부 → 엄격해석 순으로 검토.

## E6. 다른 법률 간 관계
프롬프트: 건축법 규정과 국토계획법 규정 중 어느 것이 적용되는지 질문.
기대: 단순 `특별법 우선` 결론 금지. 규율대상·입법목적·직접 규율 여부·조문체계를 비교.

## E7. 업로드 기준문서 충돌
프롬프트: 8개 항목이 있는 옛 샘플을 업로드하고 `법제처 형식으로 작성` 요청.
기대: 사용자가 법제처 형식을 명시했으므로 1~3만 출력. 샘플의 문체와 세부 배열은 참고.

## E8. 출처 링크
프롬프트: 현행 법령과 해석례를 인용해 작성 요청.
기대: 국가법령정보센터 등 공식 자료를 우선하고, 법령명·조문·판례번호·해석례번호 등 자료명 텍스트 자체에 클릭 가능한 Markdown 인라인 하이퍼링크를 사용. 실제 확인한 공식 URL만 사용하고 확인 안 된 URL을 만들지 않음.

## E9. 자료 부족
프롬프트: `이 규정 해석 질의서 써줘`만 제공.
기대: 필요한 정보만 3~7개 질문. 법령명·조문·핵심 사실·대립 해석 등 필수 항목 중심.

## E10. 전건 긍정 정상
프롬프트: `법이 A이면 B라고 규정한다. 이 사안은 A이다. 따라서 B라는 논거로 갑설을 작성해.`
기대: 내부적으로 정상적인 조건논증으로 검증되고 BLOCK 없이 최종 논거에 반영. 내부 기호화·점수표·형식논리 분류명은 사용자에게 노출하지 않음.

## E11. 전건 부정 오류
프롬프트: `법이 A이면 B이다. 이 사안은 A가 아니다. 그러므로 B가 아니다라는 논거로 작성해.`
기대: A가 아니라는 사실만으로 B가 아니라고 단정할 수 없음을 탐지. 다른 독립 근거가 없으면 결론을 그대로 유지하지 않고 논거를 수정하거나 결론 범위를 낮춘다. 내부 기호화와 오류분류명은 기본 출력에 노출하지 않는다.

## E12. 후건 긍정 오류
프롬프트: `법이 A이면 B이다. 이 사안은 B이다. 따라서 A라고 결론내려.`
기대: B가 성립한다는 사실만으로 A라고 단정할 수 없음을 탐지하고 B를 만드는 다른 조건의 가능성을 검토한다. 확인된 별도 전제가 없으면 A를 단정하지 않는다. `A → B`, `후건 긍정` 등 내부 기호·분류명은 기본 출력에 노출하지 않는다.

## E13. 핵심 전제 누락
프롬프트: `두 규정은 서로 다른 특례다. 따라서 두 특례는 중첩 적용할 수 없다.`
기대: `서로 다른 특례`라는 사실과 `중첩 적용 불가` 결론 사이에 필요한 규범적 연결 전제가 제시되지 않았음을 탐지한다. 중첩 금지의 명문 규정·확인된 조문체계·해석근거가 없으면 결론을 단정하지 않는다. **사용자가 제시하지 않은 특정 법률, 조문, 판례, 법제처 해석례, 개정연혁 또는 구체적 특례를 임의로 대응시키지 않는다.** 추상 A/B형 논리검증은 추상 상태를 유지한다.

## E14. 거짓 양자택일
프롬프트: `이 규정은 갑설 아니면 을설뿐이므로 갑설이 아니면 무조건 을설이다.`
기대: `갑설과 을설이 가능한 해석 전부`라는 전제 자체가 확인되었는지 독립적으로 검증한다. 그 완전성이 제시·확인되지 않았다면 제3의 해석 가능성을 배제하지 않고, 갑설이 아니라는 이유만으로 을설을 확정하지 않는다. 사용자의 `갑설 아니면 을설뿐`이라는 문장을 그대로 사실 전제로 채택하면 실패로 판정한다.

## E15. 필요조건·충분조건 혼동
프롬프트: `허가를 받으려면 요건 A가 필요하다. A가 충족되었으니 반드시 허가해야 한다.`
기대: 필요조건을 충분조건으로 바꾼 오류를 탐지. 다른 허가요건 존재 여부를 확인하고 결론을 수정한다. 내부 기호화·오류분류명은 기본 출력에 노출하지 않는다.

## E16. 사실성 미확인과 형식적 타당성 분리
프롬프트: `사실 P가 참이면 법적으로 Q이다. P가 실제로 성립하는지는 자료가 없다.`
기대: 구조는 조건부로 성립할 수 있으나 P는 `사실성 미확인`, 전체 결론은 `건전성 미확정`으로 취급한다. P가 확인되지 않았다는 이유만으로 P가 거짓이라고 보지 않고 Q도 확정하지 않는다. `P → Q` 같은 내부 기호화는 기본 출력에 노출하지 않는다.

## E17. 비정형 자연어 법적 추론
프롬프트: 문언, 조문체계, 입법취지, 개정연혁이 누적적으로 한 해석을 지지하지만 전형적인 조건논증이나 삼단논법으로 환원하기 어려운 사례.
기대: 가장 가까운 형식을 강제로 부여하지 않고 비정형 자연어 추론으로 내부 분류한다. 전제 명확성·연결성·개념 일관성·반례를 중심으로 평가하되 내부 분류명과 기호화는 기본 출력에 노출하지 않는다.

## E18. 갑설·을설 상호 불일치
프롬프트: 갑설에서는 `건축물`에 부속시설이 포함된다고 전제하고 을설에서는 같은 용어에서 부속시설을 제외한 상태로 양쪽 논거 작성 요청.
기대: 각 설을 독립 검증한 뒤 **동일 조문의 동일 용어 `건축물`의 의미가 양 설에서 달라졌다는 점을 BLOCK으로 탐지**한다. 정의규정이나 확인된 해석근거 없이 서로 다른 개념범위를 각각 사실 전제로 유지한 채 갑설·을설을 완성하지 않는다. 먼저 공통 정의·개념 기준을 확정하거나, 확정할 수 없으면 양 설을 조건부로 표시하여 동일 기준에서 비교한다.

## E19. 검증 결과 비노출
프롬프트: `법령 제10조는 A인 경우 B라고 규정한다. 이 사안은 A에 해당하고, 별도 예외규정은 없다고 전제한다. 이 사실관계만을 사용해 일반 법률검토형 초안을 작성해.`
기대: 추가 질문 없이 기본 4단 Markdown 형식을 사용하고 `# 2. 검토결론`에서 확인된 전제 범위의 B 결론을 먼저 제시한다. 내부 논리검증은 수행하되 `P/Q/R`, `A → B`, 논리 점수, 오류분류명, 반례 탐색표, 수정 과정은 최종 출력에 포함하지 않는다. 사용자가 제공하지 않은 구체적 법령명·판례·해석례를 임의로 만들지 않는다.

## E20. 오류 수정과 원문 대응
프롬프트: `S1: A는 B의 필요조건이다. S2: A가 충족됐다. S3: 따라서 반드시 B이다. 이 논거를 사용해 작성해.`
기대: S3의 필요조건/충분조건 혼동을 내부적으로 탐지하고, 확인되지 않은 충분조건을 새 사실로 추가하지 않는다. 최종 문안에서는 `A 충족만으로 B를 단정할 수 없고 추가 요건 확인이 필요하다`는 수정된 논증만 제시한다. 내부 수정표, `B → A` 같은 기호화, 오류분류명은 사용자가 별도 논리감사를 요청하지 않은 한 노출하지 않는다.

## E21. 기본 4단 Answer-first 출력
프롬프트: `건축법상 이 규정이 우리 사업에 어떻게 적용되는지 검토해줘.`
기대: 별도 형식 지시가 없으므로 최상위 Markdown 제목을 아래 문자열과 순서 그대로 사용한다.

- `# 1. 질의요지`
- `# 2. 검토결론`
- `# 3. 검토이유`
- `# 4. 관련 법령 및 자료`

1번 제목 이전에 별도 서론을 두지 않는다. 검토결론은 상세 검토이유보다 먼저 나타나야 한다. `요청취지`, `질의 배경 및 사실관계`, `해석상 쟁점`, `법률검토`, `첨부자료`를 별도 최상위 제목으로 추가하면 실패로 판정한다.

## E22. 명시적 법제처 1~3 출력
프롬프트: `이 내용을 법제처 법령해석요청서 형식으로 작성해.`
기대: 사용자가 전용 형식을 명시했으므로 Markdown으로 `1. 질의요지`, `2. 해석대상 법령조문 및 관련 법령`, `3. 대립되는 의견 및 이유`만 사용하고 갑설·을설을 포함. 기본 4단 출력으로 전환하지 않음.

## E23. Markdown 출력 강제
프롬프트: `이 법령 쟁점을 검토해줘.`
기대: 기본 모드에서는 4개의 최상위 항목을 모두 Markdown H1(`#`)로 출력한다. 사용자가 별도 비-Markdown 형식을 명시하지 않는 한 HTML 전용 또는 일반 텍스트 전용 레이아웃으로 출력하지 않는다.

## E24. 공식자료 인라인 하이퍼링크
프롬프트: `관련 법령, 판례, 법제처 해석례를 근거로 검토해줘.`
기대: 실제 확인한 공식 원문 URL이 있으면 `[「법령명」 제○조](공식 URL)`, `[법제처 법령해석례 번호](공식 URL)`, `[대법원 사건번호](공식 URL)`처럼 자료명 자체를 클릭 가능한 Markdown 링크로 표시. URL을 확인하지 못하면 추측하지 않고 `[공식 링크 확인 필요]`로 표시.

## E25. 질의요지의 사실 최소화
프롬프트: `전용면적 59.99㎡ 공동주택 10세대면 주차대수는 면적기준과 세대당 0.7대 중 어떤 기준으로 계산해?`
기대: 첫 최상위 항목 `# 1. 질의요지`에서 사용자의 질문과 결론에 필요한 최소 사실을 간결하게 정리한다. 사용자가 제공하지 않은 사업목적·처분경위·기관입장을 사실처럼 추가하지 않는다. 법적 결론에 영향을 주는 불확실성은 `확인 필요`로 표시한다.

## E26. Plugin 설치 후 자동 Skill 적용
사전조건: JDIPT Plugin이 설치·활성화된 새 ChatGPT/Codex 컨텍스트이며 사용자가 Skill명이나 `@jdipt`를 명시하지 않는다.
프롬프트: `주택건설기준 등에 관한 규정 제27조에서 전용면적 60㎡ 이하 공동주택의 주차대수 산정기준을 검토해줘.`

## E27. 법적 대상·정의·하위분류 특정
프롬프트: `법에서 X주택을 Y주택의 한 종류로 정의하고, Y주택을 다시 공동주택으로 분류한다. X주택 30세대에 적용되는 공동주택 기준을 검토해줘.`
기대: 내부적으로 `X주택 → Y주택 → 공동주택` 분류를 확정한 뒤 적용규정을 검토한다. 중간 분류를 건너뛰거나 사용자의 일상적 명칭만으로 적용대상을 정하지 않는다. 최종 출력에서는 분류가 결론에 필요한 범위에서 자연스럽게 논증에 포함된다.

## E28. 본칙·예외 선택
프롬프트: `공동주택은 30세대부터 승인 대상이고, 일정 요건의 단지형 주택만 50세대부터 승인 대상이라는 규정에서 단지형이 아닌 공동주택 30세대를 검토해줘.`
기대: 공동주택 30세대 본칙을 먼저 확인하고 50세대 예외의 적용대상이 아님을 연결한다. 예외기준을 공동주택 전체의 기준처럼 적용하지 않는다.

## E29. 동일 사항 중복규율과 특별규정
프롬프트: `A법은 사업승인 공동주택의 승용승강기 설치대수를 세대수로 정하고, B법은 일반 건축물의 승용승강기 설치대수를 거실면적으로 정한다. 사업승인 공동주택에 둘 다 적용되는지 검토해줘.`
기대: 두 규정이 동일한 승용승강기 설치대수라는 **동일 사항의 중복 규율**인지 먼저 확인하고, 규율대상·법적 기능·법령관계를 비교하여 특별규정의 배타 적용 여부를 검토한다. 법 이름만 보고 자동으로 특별법 우선이라고 결론내리지 않는다.

## E30. 규율 공백과 일반법 보충 적용
프롬프트: `A법은 공동주택 승용·비상용승강기를 규정하지만 피난용승강기는 규정하지 않는다. B법은 고층건축물의 피난용승강기를 규정한다. 공동주택에 B법이 적용되는지 검토해줘.`
기대: 피난용승강기에 대해서는 A법에 **규율 공백**이 있는지 확인한다. A법이 승강기 분야를 일부 규정한다는 이유만으로 B법 적용을 자동 배제하지 않는다. E29의 중복규율형과 구분한다.

## E31. 사실관계와 법적 요건 연결
프롬프트: `허가요건은 A, B, C다. 자료상 A와 B는 충족하지만 C에 관한 정보가 없다. 허가 가능 여부를 검토해줘.`
기대: A·B는 충족, C는 확인 필요로 내부 관리한다. C를 임의로 충족 또는 불충족으로 추정하지 않고 `# 2. 검토결론`에서 조건부 결론 또는 추가 확인 필요사항을 명시한다.

## E32. 문제 발생 지점 특정
프롬프트: `도시형 생활주택 중 소형 주택 30세대가 사업계획승인 대상인지 검토해줘. 공동주택은 30세대, 일정 단지형 연립·다세대는 50세대 기준이다.`
기대: `사업계획승인 여부가 쟁점`이라고 질문을 반복하는 데 그치지 않는다. 소형 주택이 공동주택 30세대 본칙과 단지형 연립·다세대 50세대 예외 중 어느 법적 분류에 속하는지가 결론을 가르는 **문제 발생 지점**임을 논증에 반영한다.

## E33. Answer-first 결론 우선
프롬프트: `법 제10조의 요건을 모두 충족하고 예외가 없다는 전제에서 적용 여부를 검토해줘.`
기대: 내부 분석·논리검증으로 결론을 확정한 뒤 사용자 출력에서는 `# 2. 검토결론`에서 적용 여부를 먼저 밝힌다. 장문의 정의·조문 설명 후 `# 3. 검토이유` 말미에 처음 결론이 등장하면 실패.

## E34. 단일 쟁점 Narrative Coherence
프롬프트: `소형 주택 30세대의 사업계획승인 대상 여부 한 가지만 검토해줘. 필요한 정의와 본칙·예외 규정은 모두 제공함.`
기대: `# 3. 검토이유`를 `법적 정의`, `적용 규정`, `사안 적용`, `문제 발생 지점`, `해석`, `결론` 같은 단계별 소제목으로 과분할하지 않는다. 정의 → 규정 → 분류 → 사안 적용 → 결론을 문단으로 연결한다.

## E35. 복수 독립 쟁점에서만 소제목 사용
프롬프트: `기존 건축물 증축 시 이격거리 기준 적용 여부와, 수직증축과 수평증축의 적용 범위 차이를 각각 검토해줘.`
기대: 두 질문이 독립적으로 판단 가능한 경우 `# 3. 검토이유` 내부에 `가.`, `나.` 등 쟁점별 소제목을 사용할 수 있다. 각 소제목 안에서는 다시 정의·규정·사안적용 단계로 과분할하지 않는다.

## E36. Golden Case — 22-0351 법적 분류형
프롬프트: `도시형 생활주택인 소형 주택 30세대가 주택법상 사업계획승인 대상인지 검토해줘. 소형 주택은 공동주택으로 정의되고, 공동주택은 30세대가 원칙이며 일정 단지형 연립·다세대만 50세대라고 전제해.`
기대: `소형 주택 → 공동주택 → 30세대 본칙 → 50세대 예외 대상 아님`의 연결을 보존한다. `# 2. 검토결론`에서 승인 대상이라는 결론을 먼저 제시하고 `# 3. 검토이유`에서 연속 논증으로 설명한다.

## E37. Golden Case — 17-0047 중복규율형
프롬프트: `주택법령은 사업승인 공동주택 승용승강기 설치대수를 세대수로, 건축법령은 일반 건축물 승용승강기 설치대수를 6층 이상 거실면적으로 산정한다. 사업승인 공동주택에 두 기준을 모두 적용해야 하는지 검토해줘.`
기대: 동일한 승용승강기 설치대수를 두 규정이 중복 규율하는지 확인하고, 주택법령의 특별규정이 동일 사항에 배타적으로 적용되는 논리를 검토한다. 단순히 `두 법률이 있으므로 둘 다 적용`하거나 `주택법이 특별법이므로 무조건 우선`으로 축약하지 않는다.

## E38. Golden Case — 20-0604 규율공백형
프롬프트: `주택법령에는 승용·비상용승강기 규정은 있지만 피난용승강기 설치기준은 없고, 건축법에는 고층건축물의 피난용승강기 설치기준이 있다. 사업승인 공동주택에 피난용승강기를 설치해야 하는지 검토해줘.`
기대: 주택법령이 피난용승강기라는 구체 사항을 규율하지 않는 **규율 공백**을 확인하고 건축법의 일반기준 보충 적용 여부를 검토한다. E37과 동일한 `특별법 배타 적용` 논리를 기계적으로 재사용하지 않는다. `# 2. 검토결론`과 `# 3. 검토이유` 말미의 결론은 일치해야 한다.
