# 내부 논리검증 절차

이 문서는 법령해석요청서와 내부 법률검토 초안을 최종 출력하기 전에 수행하는 **비공개 내부 검증 절차**를 정의한다. 목적은 자연어 법률논증의 구조적 오류, 전제 누락, 개념 이동, 과도한 결론을 탐지하고 수정하는 것이다.

논리검증 결과 자체는 사용자가 명시적으로 요구하지 않는 한 최종 답변에 표시하지 않는다. 검증에서 발견한 문제는 반드시 최종 논증에 반영한다.

## 1. 기본 원칙

### 추상 fixture 방향성 결론 BLOCK

가상·추상 fixture에서 결론을 좌우하는 핵심 용어의 관계 또는 참조된 별표·별지서식의 기능이 미해결이면, 그 미해결 상태를 한쪽 방향의 결론으로 변환하지 않는다.

다음 추론은 **BLOCK**한다.

- `금지 규정이 없다` → 허용·신청 가능·승인 가능
- `제한 규정이 없다` → 요건 충족 또는 적용 가능
- `기존 시설을 배제하지 않는다` → 기존 시설도 포함
- `별지에 특정 유형만 있다` → 그 유형만 허용 또는 다른 유형은 금지
- `별지는 신청서다` → 단순 절차·행정양식일 뿐 실체적 의미가 없음
- `상위법에 제한이 없다` → 별지의 분류는 효력이 약함
- `신설 / 증설`, `신규 설치 / 증설` 같은 신청 유형 → 기존 건축물 활용·전환이 어느 유형에 속한다고 임의 분류

이 BLOCK이 걸린 경우 `가능성이 인정된다`, `원칙적으로 가능하다`, `타당하다`, `자연스럽다`, `배제할 근거가 없다`, `허가 가능성은 열려 있다`처럼 **방향성을 암시하는 표현도 결론으로 사용하지 않는다.** 제공된 전제만으로 결론을 확정할 수 없다고 중립적으로 유지한다.

**미확인 `신설 / 증설` 의미는 승인 방향을 지지하거나 반박하는 근거가 아니다.** 신청유형의 의미·법적 기능·위임관계와 상위규정의 관계가 해결되지 않은 동안 `# 2. 검토결론`에서는 **현재 전제만으로 승인 가능 여부를 판단할 수 없다**고 유지한다. `승인 가능성을 뒷받침`, `승인 가능성이 높`, `승인받기 어렵`, `승인 가능성은 열려` 같은 비대칭 평가 문구가 남아 있으면 BLOCK하고 중립 문장으로 재작성한다.

미제공 별표·별지서식에 있을 수 있는 문구를 `만약 ○○라고 정한다면`, `○○가 기재되어 있다면`처럼 구체적으로 새로 만들어 논증의 분기로 사용하지 않는다. 필요한 확인사항은 `별지의 실제 문언과 그 법적 기능 확인 필요`처럼 추상적으로만 적는다.

또한 fixture에 없는 신청·변경·보완·등록·운영·용도변경 등의 별도 절차나 행정상 우회 방법을 생성하지 않는다.

- 검증 대상은 최종 문안 직전의 핵심 논증이다. 법제처 모드에서는 **갑설과 을설을 각각 독립 검증한 뒤 상호 비교**한다.
- 원문에 없는 전제를 사실인 것처럼 추가하지 않는다. 연결 전제가 필요하지만 제시·확인되지 않았으면 `전제 누락`으로 표시한다.
- **추상 입력 보존:** 사용자가 A/B/P/Q 같은 추상 기호나 가상 규칙만 제시하고 실체조사를 요청하지 않은 경우, 이를 특정 법률·조문·판례·법제처 해석례·개정연혁·실제 사실관계에 임의로 대응시키지 않는다. 논리검증은 추상 상태를 유지한다.
- 추상 입력의 누락 전제를 메우기 위해 MCP·웹 검색으로 임의의 구체 법령사례를 찾아 연결하지 않는다. 사용자가 실체조사·사례 확인을 명시적으로 요청한 경우에만 별도 조사하고, 그 결과를 원래 추상 전제와 구분한다.
- **선택지 완전성:** `갑설 또는 을설`, `P 또는 Q`와 같은 선언에서 그 선택지가 가능한 경우 전부라는 사실 자체를 독립된 전제로 검증한다. 완전성이 제시·확인되지 않았으면 제3의 가능성을 배제하지 않는다.
- **동일 용어 의미 변경:** 갑설·을설 또는 한 논증 안에서 동일한 법률용어의 의미·범위가 달라지면 핵심 개념 불일치로 보고 BLOCK 후보로 처리한다. 정의규정이나 확인된 해석근거 없이 서로 다른 의미를 유지한 채 결론을 만들지 않는다.
- 정형 논리로 정확히 환원되지 않는 법적 추론을 억지로 삼단논법이나 조건논증으로 만들지 않는다. 이 경우 `비정형 자연어 추론`으로 분류하고 연결성·개념 일관성을 중심으로 평가한다.
- 형식적 타당성과 전제의 사실성·법적 근거를 구분한다. 형식이 타당해도 핵심 전제가 미확인이라면 `건전성 미확정`이다.
- 사실성 미확인은 논리 점수에서 직접 감점하지 않는다. 다만 사실성 미확인 때문에 전제가 불명확하거나 적용 여부 자체가 정해지지 않으면 관련 구조 항목에서만 감점할 수 있다.
- 논리 점수는 법률적 정답 확률이나 법률자문 신뢰도를 의미하지 않는다.
- 사용자가 논리감사나 형식논리 설명을 요구하지 않은 경우 **내부 오류분류명**, 기호화, 점수, 반례표, 수정표는 최종 사용자 문안에 노출하지 않는다. 최종 문안에는 오류를 교정한 일반 법률검토 문장만 반영한다.

### 동일 용어 상충 전제 Hard Stop

갑설·을설 또는 복수 논증이 **같은 조문의 같은 법률용어에 서로 다른 의미·범위를 전제로 부여**하고, 그 차이를 정당화할 정의규정·문언·확인된 근거가 제공되지 않은 경우에는 다음을 강제한다.

- 두 의미를 각각 참인 전제로 받아들여 갑설·을설의 실체 논거를 만들어 주지 않는다.
- 사용자가 `양쪽 논거를 작성해줘`라고 요청했더라도, 먼저 동일 용어의 개념범위가 충돌한다는 점을 핵심 문제로 특정한다.
- 공통 정의·개념 기준이 확정되지 않으면 어느 한 의미를 채택하거나 양쪽 의미를 병렬 유지하지 않는다.
- 최종 답변에서는 `공통 기준이 확정되지 않아 현재 전제만으로는 양 설의 실체적 우열 또는 타당한 논거를 구성할 수 없다`는 취지의 조건부 결론을 사용한다.
- 각 설이 **주장하고 있는 전제 자체**를 요약하는 것은 가능하지만, 그 전제가 맞다고 가정하여 fixture 밖의 기능적·구조적·목적론적 이유를 새로 생성하지 않는다.
- 이 Hard Stop이 발동한 경우 최종 답변에서 `## 갑설`, `## 을설` 아래에 서로 충돌하는 개념범위를 전제로 한 실체 논거를 각각 전개하지 않는다. 필요한 경우 각 설의 주장범위를 한 문장씩 요약한 뒤, 공통 개념 기준 미확정 때문에 실체적 우열 판단이 불가능하다고 설명한다.


## 2. 문장·논증 단위 분해

1. 원문에 문장 번호가 있으면 그 번호를 유지한다.
2. 번호가 없으면 내부적으로 `S1`, `S2`, `S3`처럼 부여한다.
3. 하나의 문장에 서로 독립된 명제가 둘 이상 있으면 `S2-a`, `S2-b`처럼 나눈다.
4. 각 논증마다 `전제 → 중간결론 → 최종결론`의 관계를 표시한다.
5. 갑설은 `A-S1...`, 을설은 `B-S1...`처럼 구분해 서로 다른 전제가 섞이지 않게 한다.

## 3. 기호화 또는 표준형 변환

각 논증을 가능한 범위에서 `P`, `Q`, `R` 등의 기호로 변환하고, 각 기호 옆에 대응하는 원문 명제와 문장 번호를 기록한다.

### 기본 표기

- 조건: `P → Q`
- 선언: `P ∨ Q`
- 부정: `¬P`
- 논리곱: `P ∧ Q`
- 결론: `∴ Q`

### 정규화 규칙

- 삼단논법: 대전제 / 소전제 / 결론으로 구분한다.
- 조건 논증: `P → Q`를 기본형으로 한다.
- 선언 논증: `P ∨ Q`로 표현하되 포괄적 논리합인지 배타적 논리합인지 구분한다.
- 이중부정: `¬¬P`와 `P`의 관계를 확인하되 자연어의 완곡 표현, 부분부정, 부정 범위의 중의성을 별도로 확인한다.
- 한 자연어 문장이 복수의 합리적 형식으로 해석되면 가능한 형식을 구분하고 하나로 임의 확정하지 않는다.
- 형식화에 필요한 전제가 원문이나 확인된 법적 근거에 없으면 빈자리를 `전제 누락`으로 둔다.

예시 내부 메모:

```text
P (S1) = 법령이 요건 A를 충족하면 효과 B가 발생한다고 규정한다.
Q (S2) = 이 사안이 요건 A를 충족한다.
C (S3) = 효과 B가 발생한다.

P: A → B
Q: A
∴ B
형식: 전건 긍정
```

이 예시는 내부 메모 형식이며 사용자용 최종 문안에 그대로 출력하지 않는다.

## 4. 적용 논리 형식 판별

우선 다음 형식을 판별한다.

### 전건 긍정

```text
P → Q
P
∴ Q
```

형식적으로 타당하다.

### 후건 부정

```text
P → Q
¬Q
∴ ¬P
```

형식적으로 타당하다.

### 전건 부정 오류 탐지

```text
P → Q
¬P
∴ ¬Q
```

원칙적으로 결론이 도출되지 않는다. 다른 독립 전제가 없는지 확인한다.

### 후건 긍정 오류 탐지

```text
P → Q
Q
∴ P
```

원칙적으로 결론이 도출되지 않는다. `Q`를 발생시키는 다른 조건이 가능한지 반례를 검토한다.

### 삼단논법

해당되는 경우 대개념·소개념·매개념과 각 전제의 양·질을 확인한다. 자연어 법률논증이 전형적인 정언삼단논법이 아니면 억지로 이 형식을 부여하지 않는다.

### 선언 명제

`P ∨ Q`에서 다음을 확인한다.

- 포괄적 논리합인지 배타적 논리합인지
- 두 선언지가 실제로 상호 배타적인지
- 가능한 경우를 모두 포괄하는지
- `P ∨ Q`의 **선택지 완전성**을 뒷받침하는 별도 근거가 있는지
- 제3의 가능성을 배제해 거짓 양자택일을 만들고 있지 않은지

사용자가 `P 또는 Q뿐이다`, `갑설 아니면 을설뿐이다`라고 단정했더라도 그 문장을 자동으로 참인 전제로 채택하지 않는다. 가능한 경우 전부라는 점이 확인되지 않으면 제3의 가능성을 열어 둔다.

전형적 형식에 정확히 들어맞지 않으면 `비정형 자연어 추론`으로 분류한다.

## 5. 전제별 검토

각 전제마다 다음을 확인한다.

| 항목 | 검토 내용 |
|---|---|
| 명확성 | 문장의 의미와 범위가 한 가지로 특정되는가 |
| 명시 여부 | 원문 또는 확인된 근거에 실제 존재하는가 |
| 개념 정의 | 핵심 용어가 앞뒤에서 같은 의미로 사용되는가 |
| 일관성 | 다른 전제와 모순되지 않는가 |
| 관련성 | 결론 도출과 직접 관련되는가 |
| 충분성 | 결론까지 연결하는 데 필요한 전제가 갖추어졌는가 |
| 사실성 상태 | `확인`, `사실성 미확인`, `확인 불가` 중 무엇인가 |

외부 확인이 필요한 사실 전제는 근거를 확인하기 전까지 참·거짓으로 단정하지 않고 `사실성 미확인`으로 둔다.

법령·판례·해석례에서 가져온 법적 전제는 공식 원문과 현행성 또는 적용시점을 확인한다. 핵심 전제가 미확인이라면 형식적 타당성과 별도로 `건전성 미확정`이라고 기록한다.

## 6. 추론 타당성 검토

각 논증에 대해 다음을 확인한다.

- 제시된 전제만으로 결론이 형식적으로 도출되는가
- 필요조건을 충분조건으로, 또는 충분조건을 필요조건으로 바꾸지 않았는가
- 인과관계와 상관관계를 혼동하지 않았는가
- 중간 추론 단계가 빠져 논리적 비약이 생기지 않았는가
- 결론이 전제가 허용하는 범위보다 더 강한 주장을 하지 않는가
- 예외·특례·완화 규정의 적용범위를 명시적 근거 없이 확장하지 않았는가
- 동일 용어가 서로 다른 조문에서 쓰였다는 이유만으로 동일한 기능·효과를 가진다고 전제하지 않았는가
- 법률 간 관계를 단순한 `특별법 우선`만으로 결론 내리지 않고 규율대상·목적·직접 규율 여부를 확인했는가
- 추상 논리 시나리오에서 원문에 없는 구체 법률관계나 사례를 연결 전제로 새로 만들지 않았는가

결론이 도출되지 않을 때 필요한 연결 전제를 추측하여 삽입하지 않는다. 어떤 기능의 전제가 빠졌는지만 `전제 누락`으로 설명한다.

## 7. 오류·전제 누락·반례 탐색

다음 오류를 체계적으로 탐지한다.

- 순환논증
- 성급한 일반화
- 개념의 미끄러짐
- 모순
- 거짓 양자택일
- 전건 부정
- 후건 긍정
- 근거 부족
- 전제 누락
- 반례 가능성

각 탐지 항목은 내부적으로 다음 형식으로 기록한다.

| 문장/문단 | 오류 유형 | 문제 추론 | 판정 근거 | 반례/대안 | 상태 |
|---|---|---|---|---|---|
| S3 | 전제 누락 | P와 Q만으로 C를 단정 | C를 연결하는 규범 전제가 없음 | 해당 전제가 없으면 C가 성립하지 않는 경우 | 확정 |

상태는 `확정`, `가능성`, `판정 불가`만 사용한다.

반례는 가능한 경우 **원문의 전제를 모두 만족하면서 결론을 거짓으로 만드는 경우**를 우선한다. 실제 법령상 예외나 대체 원인이 있는 경우에는 그 존재 여부를 별도 확인한다. 추상 논리 테스트에서는 실제 법령사례를 임의로 만들어 반례처럼 제시하지 않고, 추상 반례 가능성만 검토한다.

## 8. 문단별 및 전체 내부 평가

가능한 경우 다음 내부 표를 만든다.

| 문장 또는 문단 번호 | 핵심 논증 | 형식적 타당성 | 전제 명확성 | 연결성 | 개념 일관성 | 판정 | 점수 | 확신 수준 | 근거 |
|---|---|---|---|---|---|---|---:|---|---|

### 배점 및 항목별 점수

각 문단 및 전체 논증에 대해 다음 네 항목의 점수를 **각각 기록한 뒤** 합산한다.

| 평가 항목 | 배점 | 내부 기록 |
|---|---:|---|
| 형식적 타당성 | 50점 | `__/50` |
| 전제의 명확성 | 20점 | `__/20` |
| 근거와 결론의 연결성 | 20점 | `__/20` |
| 개념 일관성과 반례 대응력 | 10점 | `__/10` |

총점 구간은 정확히 다음을 사용한다.

- `타당`: 85~100점
- `부분 타당`: 65~84점
- `취약`: 40~64점
- `부당`: 0~39점

`확신 수준`은 분석 근거의 충분성에 따라 `높음`, `중간`, `낮음`으로만 표시한다. 사실의 참·거짓 확률처럼 표현하지 않는다.

문단별 검토 후 전체 논증에 대해 다음을 별도로 기록한다.

```text
형식적 타당성 점수: __/50
전제의 명확성 점수: __/20
근거와 결론의 연결성 점수: __/20
개념 일관성과 반례 대응력 점수: __/10
종합 점수: N/100
4단계 판정: 타당 | 부분 타당 | 취약 | 부당
형식적 타당성: 타당 | 일부 미도출 | 부당 | 비정형
건전성 상태: 확인 | 미확정 | 불충분
```

## 9. 갑설·을설 상호 비교

법제처 모드에서는 각 설의 개별 검증 후 다음을 추가 확인한다.

- 양쪽이 동일한 사실관계를 전제로 하는가
- 동일한 법률용어를 서로 다른 의미로 바꾸어 사용하지 않는가
- 한쪽만 필요한 조문·정의규정·예외규정을 누락하지 않았는가
- 한쪽에만 확인되지 않은 숨은 전제가 들어가지 않았는가
- 동일한 해석원칙을 양쪽에 일관되게 적용했는가
- 갑설과 을설이 실제로 서로 대립하는 명제인지, 서로 다른 질문에 답하고 있지는 않은가

**동일 용어 의미 변경**이 확인되면 양 설을 그대로 완성하지 않는다. 먼저 다음 순서로 보정한다.

1. 해당 용어의 정의규정 또는 확인된 해석근거가 있는지 확인한다.
2. 공통으로 적용할 개념 범위를 정한다.
3. 공통 기준에서 갑설·을설을 다시 구성한다.
4. 공통 개념범위를 확정할 수 없으면 `의미 범위 확인 필요`로 두고 각 설을 조건부로 표현한다.

한쪽 논거가 현저히 약해도 인위적으로 50:50으로 맞추지 않는다.

## 10. 수정 제안 작성

검증에서 문제가 발견되면 문제 지적에 그치지 않고 원문의 논지를 유지하면서 더 타당한 구조로 수정안을 만든다. 이 수정안은 **내부 작업물**이며 최종 문안에 반영한다.

가능하면 다음 대응표를 내부적으로 사용한다.

| 원래 문장 번호 | 수정 전 문제 | 수정 원칙 | 수정 예시 | 추가가 필요한 전제 |
|---|---|---|---|---|
| S3 | 결론이 전제보다 강함 | 결론 범위를 전제가 지지하는 수준으로 축소 | `따라서 B라고 단정하기보다 B로 해석될 여지가 있다.` | 없음 |

수정 규칙:

- 원문의 사실 주장이나 의도를 임의로 바꾸지 않는다.
- 가능한 경우 수정문을 원래 문장 번호와 대응시킨다.
- 누락 전제를 보완하는 예시는 반드시 `추가가 필요한 전제`로 명시하여 원문 전제와 구분한다.
- 추가 전제는 공식 법령·판례·해석례 또는 사용자가 제공한 사실에서 실제로 확인되기 전까지 확정 전제로 취급하지 않는다.
- 사실성 미확인 전제를 확정적 사실처럼 고쳐 쓰지 않는다.
- 추상 입력에는 추상 수정문을 사용하고 구체 법령·사실을 새로 만들어 넣지 않는다.
- `수정 전 문제 → 수정 원칙 → 수정 예시`의 대응 관계가 명확해야 한다.
- 수정 때문에 새로운 전제나 더 강한 결론이 생기지 않았는지 다시 확인한다.

## 11. 수정 및 재검증 Gate

최초 논증을 검증한 뒤 바로 최종 출력하지 않는다.

### BLOCK — 수정 후 반드시 재검증

다음 중 하나가 `확정`이면 논증을 수정하고 같은 절차를 다시 수행한다.

- 명백한 모순
- 전건 부정 또는 후건 긍정에 의존한 결론
- 핵심 연결 전제 누락
- 결론이 전제보다 명백하게 강함
- 핵심 개념의 의미가 추론 도중 변경됨
- 갑설·을설에서 동일한 법률용어의 의미가 근거 없이 달라짐
- 선택지 완전성이 확인되지 않았는데 거짓 양자택일이 결론의 필수 근거임
- 존재하지 않거나 확인되지 않은 법적 연결관계를 사실처럼 추가함
- 추상 논리 시나리오를 사용자가 제시하지 않은 구체 법률·사례에 임의 대응하여 전제를 보충함
- 미확인 `신설 / 증설` 의미를 근거로 승인 가능성을 지지하거나 반박하는 방향성 판단을 작성함

누락 전제를 확인할 수 없다면 만들어 넣지 말고 결론을 조건부로 낮추거나 `확인 필요`로 표시한다.

### Counterevidence BLOCK

현재 실행에서 잠정 결론에 중대한 영향을 줄 수 있는 반대 법적 자료가 실제로 발견되었는데, 그 자료의 의미·법적 기능·위임근거·상위법과의 관계를 해결하지 않은 채 확정 결론을 내리면 BLOCK한다.

이 BLOCK은 다음 순서로 해소한다.

1. 반대근거가 이 사안에 적용되는지와 그 법적 기능을 해석한다.
2. 필요한 경우 추가 공식자료를 확인한다.
3. 관계를 해결할 수 없으면 결론을 조건부로 낮춘다.
4. 결론에 필수적인 사실이나 자료가 부족하면 `확인 필요`로 처리한다.

다음 양방향 자동추론은 모두 금지한다.

- 상위법에 명시적 제한이 없다는 이유만으로 무조건 가능하다고 결론내리지 않는다.
- 별지서식 등에 제한적으로 보이는 문구가 있다는 이유만으로 무조건 불가능하다고 결론내리지 않는다.

### Referenced Source Resolution BLOCK

공식 원문에서 확인한 조문이 별표·별지서식·부표·부록 등 별도 자료를 직접 참조하고, **그 참조자료의 문언이 핵심 법적 분류·신청 유형·요건·예외 또는 결론의 강도에 영향을 줄 수 있는데 실제 문언을 확인하지 못한 경우에는 확정 결론을 BLOCK한다.**

다음은 해결된 것으로 보지 않는다.

- 상위 조문에서 별지서식의 존재만 확인하고 실제 서식을 열어보지 않은 경우
- 정부24·검색결과·2차 안내자료가 비슷한 신청 유형을 설명한다는 이유로 원문 별지서식을 대체한 경우
- `변경`이라는 단어가 있다는 이유만으로 `기존 일반 건축물의 최초 전환`과 `이미 받은 설립승인사항 변경`을 동일시한 경우
- `신설`과 `건축물 신축`을 정의·문언 근거 없이 동일시한 경우
- 반대로 `신축` 제한 문언이 없다는 이유만으로 참조된 신청 유형·서식 분류를 무시한 경우

이 BLOCK은 다음 중 하나로만 해소한다.

1. 참조자료의 실제 문언을 공식 원문에서 확인하고 그 법적 기능·상위 조문과의 관계를 설명한다.
2. 공식 원문을 끝내 확인할 수 없으면 그 확인 실패를 핵심 미해결 자료로 남기고 결론을 조건부로 낮춘다.

참조자료의 미확인 상태를 `제한 없음`, `허용`, `금지`, `자료 없음`으로 임의 변환하지 않는다.

### WARN — 표현 강도·범위를 조정

- 비정형 자연어 추론
- 사실성 미확인 전제
- 합리적인 반례 가능성
- 복수 해석 가능성
- 법적 전제의 적용범위 불명확

WARN만 있는 경우 최종 출력을 막지는 않지만 단정 수준을 근거 강도에 맞게 조정한다.

### PASS

BLOCK 항목이 없고, 필요한 수정이 반영되었으며, 핵심 전제와 결론의 연결이 설명 가능한 상태다.

## 12. 최종 생성 순서

내부 처리 순서는 다음을 기본으로 한다.

```text
자료·법령 조사
→ 잠정 결론 후 Source Completeness / Counterevidence 확인
→ 참조된 핵심 별표·별지서식 resolution 확인
→ 법적 논증 초안
→ 문장·논증 분해
→ 기호화/표준형 변환
→ 전제 검토
→ 추론 타당성 검토
→ 오류·누락·반례 탐색
→ 문단별/전체 평가
→ 갑설·을설 상호 비교
→ 수정 제안 작성
→ BLOCK 수정
→ 논리검증 재수행
→ 출처·현행성·인용 최종 검증
→ 사용자용 최종 문안 생성
→ request-format의 최종 Rendering Hard Gate 재검사
```

논리검증 메모, 기호화 표, 점수표, 반례 탐색 과정, 내부 수정표, **내부 오류분류명**은 기본 출력에 포함하지 않는다. 사용자용 최종 문안에는 검증에서 교정된 결론과 필요한 확인사항만 자연어 법률검토 문장으로 반영한다.

사용자가 논리감사·논리검증 결과 공개를 명시적으로 요청하면 원시 내부 추론과 전체 체인을 그대로 노출하지 않고, 최종 결론을 뒷받침하는 범위에서 오류 유형·필요 전제·수정 결과·근거를 요약한 검증보고서 형태로 제공한다.

## 13. 추상 fixture 전제 보존 Hard Gate

가상 법률·가상 시행령·가상 시행규칙처럼 사용자가 만든 **추상 fixture**를 검토할 때에는 사용자가 실제로 제공한 규정·정의·사실만 법적 전제로 사용한다.

- `설립`, `신설`, `전환`, `허가`, `승인` 같은 용어의 법적 의미가 fixture에 정의되어 있지 않다면, 일반적인 법률상식·통상적 의미·다른 실제 법령의 관행을 이용해 그 의미를 새 법적 정의처럼 확정하지 않는다.
- fixture에 없는 `시설`, `조직`, `책임자`, `운영기준`, `별도 기능`, `기존 지위 종료` 등의 요건을 그럴듯한 일반론이라는 이유로 새 허가·설립 요건처럼 추가하지 않는다.
- 제공되지 않은 정의나 요건이 결론을 좌우한다면 그 부분은 `정의·요건 확인 필요`로 남기고, 제공된 전제만으로 가능한 범위에서 조건부 결론을 제시한다.
- 추상 fixture에서 일반적 의미를 설명할 수는 있지만, 그 설명을 **결론을 도출하는 규범 전제**로 사용해서는 안 된다.
- 새로 만든 정의·요건·법적 효과가 결론의 필수 근거가 된 경우 `전제 누락` 및 추상 입력 훼손으로 BLOCK하고 해당 전제를 제거한 뒤 재검증한다.

이 Gate는 실제 법령을 조사하는 사건에서 확인된 정의규정·조문체계·판례·법령해석례를 사용하는 것을 금지하는 규칙이 아니다. 오직 사용자가 의도적으로 추상 상태로 구성한 fixture를 실제 법체계처럼 채워 넣는 것을 방지한다.
