# 내부 논리검증 절차

이 문서는 법령해석요청서와 내부 법률검토 초안을 최종 출력하기 전에 수행하는 **비공개 내부 검증 절차**를 정의한다. 목적은 자연어 법률논증의 구조적 오류, 전제 누락, 개념 이동, 과도한 결론을 탐지하고 수정하는 것이다.

논리검증 결과 자체는 사용자가 명시적으로 요구하지 않는 한 최종 답변에 표시하지 않는다. 검증에서 발견한 문제는 반드시 최종 논증에 반영한다.

## 1. 기본 원칙

- 검증 대상은 최종 문안 직전의 핵심 논증이다. 법제처 모드에서는 **갑설과 을설을 각각 독립 검증한 뒤 상호 비교**한다.
- 원문에 없는 전제를 사실인 것처럼 추가하지 않는다. 연결 전제가 필요하지만 제시·확인되지 않았으면 `전제 누락`으로 표시한다.
- 정형 논리로 정확히 환원되지 않는 법적 추론을 억지로 삼단논법이나 조건논증으로 만들지 않는다. 이 경우 `비정형 자연어 추론`으로 분류하고 연결성·개념 일관성을 중심으로 평가한다.
- 형식적 타당성과 전제의 사실성·법적 근거를 구분한다. 형식이 타당해도 핵심 전제가 미확인이라면 `건전성 미확정`이다.
- 사실성 미확인은 논리 점수에서 직접 감점하지 않는다. 다만 사실성 미확인 때문에 전제가 불명확하거나 적용 여부 자체가 정해지지 않으면 관련 구조 항목에서만 감점할 수 있다.
- 논리 점수는 법률적 정답 확률이나 법률자문 신뢰도를 의미하지 않는다.

## 2. 문장·논증 단위 분해

1. 원문에 문장 번호가 있으면 그 번호를 유지한다.
2. 번호가 없으면 내부적으로 `S1`, `S2`, `S3`처럼 부여한다.
3. 하나의 문장에 서로 독립된 명제가 둘 이상 있으면 `S2-a`, `S2-b`처럼 나눈다.
4. 각 논증마다 `전제 → 중간결론 → 최종결론`의 관계를 표시한다.
5. 갑설은 `A-S1...`, 을설은 `B-S1...`처럼 구분해 서로 다른 전제가 섞이지 않게 한다.

## 3. 기호화 또는 표준형 변환

각 논증을 가능한 범위에서 `P`, `Q`, `R` 등의 기호로 변환하고, 각 기호 옆에 대응하는 원문 명제와 문장 번호를 기록한다.

### 기본 표기

- 조건: `P → Q`
- 선언: `P ∨ Q`
- 부정: `¬P`
- 논리곱: `P ∧ Q`
- 결론: `∴ Q`

### 정규화 규칙

- 삼단논법: 대전제 / 소전제 / 결론으로 구분한다.
- 조건 논증: `P → Q`를 기본형으로 한다.
- 선언 논증: `P ∨ Q`로 표현하되 포괄적 논리합인지 배타적 논리합인지 구분한다.
- 이중부정: `¬¬P`와 `P`의 관계를 확인하되 자연어의 완곡 표현, 부분부정, 부정 범위의 중의성을 별도로 확인한다.
- 한 자연어 문장이 복수의 합리적 형식으로 해석되면 가능한 형식을 구분하고 하나로 임의 확정하지 않는다.
- 형식화에 필요한 전제가 원문이나 확인된 법적 근거에 없으면 빈자리를 `전제 누락`으로 둔다.

예시 내부 메모:

```text
P (S1) = 법령이 요건 A를 충족하면 효과 B가 발생한다고 규정한다.
Q (S2) = 이 사안이 요건 A를 충족한다.
C (S3) = 효과 B가 발생한다.

P: A → B
Q: A
∴ B
형식: 전건 긍정
```

## 4. 적용 논리 형식 판별

우선 다음 형식을 판별한다.

### 전건 긍정

```text
P → Q
P
∴ Q
```

형식적으로 타당하다.

### 후건 부정

```text
P → Q
¬Q
∴ ¬P
```

형식적으로 타당하다.

### 전건 부정 오류 탐지

```text
P → Q
¬P
∴ ¬Q
```

원칙적으로 결론이 도출되지 않는다. 다른 독립 전제가 없는지 확인한다.

### 후건 긍정 오류 탐지

```text
P → Q
Q
∴ P
```

원칙적으로 결론이 도출되지 않는다. `Q`를 발생시키는 다른 조건이 가능한지 반례를 검토한다.

### 삼단논법

해당되는 경우 대개념·소개념·매개념과 각 전제의 양·질을 확인한다. 자연어 법률논증이 전형적인 정언삼단논법이 아니면 억지로 이 형식을 부여하지 않는다.

### 선언 명제

`P ∨ Q`에서 다음을 확인한다.

- 포괄적 논리합인지 배타적 논리합인지
- 두 선언지가 실제로 상호 배타적인지
- 가능한 경우를 모두 포괄하는지
- 제3의 가능성을 배제해 거짓 양자택일을 만들고 있지 않은지

전형적 형식에 정확히 들어맞지 않으면 `비정형 자연어 추론`으로 분류한다.

## 5. 전제별 검토

각 전제마다 다음을 확인한다.

| 항목 | 검토 내용 |
|---|---|
| 명확성 | 문장의 의미와 범위가 한 가지로 특정되는가 |
| 명시 여부 | 원문 또는 확인된 근거에 실제 존재하는가 |
| 개념 정의 | 핵심 용어가 앞뒤에서 같은 의미로 사용되는가 |
| 일관성 | 다른 전제와 모순되지 않는가 |
| 관련성 | 결론 도출과 직접 관련되는가 |
| 충분성 | 결론까지 연결하는 데 필요한 전제가 갖추어졌는가 |
| 사실성 상태 | `확인`, `사실성 미확인`, `확인 불가` 중 무엇인가 |

외부 확인이 필요한 사실 전제는 근거를 확인하기 전까지 참·거짓으로 단정하지 않고 `사실성 미확인`으로 둔다.

법령·판례·해석례에서 가져온 법적 전제는 공식 원문과 현행성 또는 적용시점을 확인한다. 핵심 전제가 미확인이라면 형식적 타당성과 별도로 `건전성 미확정`이라고 기록한다.

## 6. 추론 타당성 검토

각 논증에 대해 다음을 확인한다.

- 제시된 전제만으로 결론이 형식적으로 도출되는가
- 필요조건을 충분조건으로, 또는 충분조건을 필요조건으로 바꾸지 않았는가
- 인과관계와 상관관계를 혼동하지 않았는가
- 중간 추론 단계가 빠져 논리적 비약이 생기지 않았는가
- 결론이 전제가 허용하는 범위보다 더 강한 주장을 하지 않는가
- 예외·특례·완화 규정의 적용범위를 명시적 근거 없이 확장하지 않았는가
- 동일 용어가 서로 다른 조문에서 쓰였다는 이유만으로 동일한 기능·효과를 가진다고 전제하지 않았는가
- 법률 간 관계를 단순한 `특별법 우선`만으로 결론 내리지 않고 규율대상·목적·직접 규율 여부를 확인했는가

결론이 도출되지 않을 때 필요한 연결 전제를 추측하여 삽입하지 않는다. 어떤 기능의 전제가 빠졌는지만 `전제 누락`으로 설명한다.

## 7. 오류·전제 누락·반례 탐색

다음 오류를 체계적으로 탐지한다.

- 순환논증
- 성급한 일반화
- 개념의 미끄러짐
- 모순
- 거짓 양자택일
- 전건 부정
- 후건 긍정
- 근거 부족
- 전제 누락
- 반례 가능성

각 탐지 항목은 내부적으로 다음 형식으로 기록한다.

| 문장/문단 | 오류 유형 | 문제 추론 | 판정 근거 | 반례/대안 | 상태 |
|---|---|---|---|---|---|
| S3 | 전제 누락 | P와 Q만으로 C를 단정 | C를 연결하는 규범 전제가 없음 | 해당 전제가 없으면 C가 성립하지 않는 경우 | 확정 |

상태는 `확정`, `가능성`, `판정 불가`만 사용한다.

반례는 가능한 경우 **원문의 전제를 모두 만족하면서 결론을 거짓으로 만드는 경우**를 우선한다. 실제 법령상 예외나 대체 원인이 있는 경우에는 그 존재 여부를 별도 확인한다.

## 8. 문단별 및 전체 내부 평가

가능한 경우 다음 내부 표를 만든다.

| 문장 또는 문단 번호 | 핵심 논증 | 형식적 타당성 | 전제 명확성 | 연결성 | 개념 일관성 | 판정 | 점수 | 확신 수준 | 근거 |
|---|---|---|---|---|---|---|---:|---|---|

### 배점

- 형식적 타당성: 50점
- 전제의 명확성: 20점
- 근거와 결론의 연결성: 20점
- 개념 일관성과 반례 대응력: 10점

총점 구간은 정확히 다음을 사용한다.

- `타당`: 85~100점
- `부분 타당`: 65~84점
- `취약`: 40~64점
- `부당`: 0~39점

`확신 수준`은 분석 근거의 충분성에 따라 `높음`, `중간`, `낮음`으로만 표시한다. 사실의 참·거짓 확률처럼 표현하지 않는다.

문단별 검토 후 전체 논증에 대해 다음을 별도로 기록한다.

```text
종합 점수: N/100
4단계 판정: 타당 | 부분 타당 | 취약 | 부당
형식적 타당성: 타당 | 일부 미도출 | 부당 | 비정형
건전성 상태: 확인 | 미확정 | 불충분
```

## 9. 갑설·을설 상호 비교

법제처 모드에서는 각 설의 개별 검증 후 다음을 추가 확인한다.

- 양쪽이 동일한 사실관계를 전제로 하는가
- 동일한 법률용어를 서로 다른 의미로 바꾸어 사용하지 않는가
- 한쪽만 필요한 조문·정의규정·예외규정을 누락하지 않았는가
- 한쪽에만 확인되지 않은 숨은 전제가 들어가지 않았는가
- 동일한 해석원칙을 양쪽에 일관되게 적용했는가
- 갑설과 을설이 실제로 서로 대립하는 명제인지, 서로 다른 질문에 답하고 있지는 않은가

한쪽 논거가 현저히 약해도 인위적으로 50:50으로 맞추지 않는다.

## 10. 수정 및 재검증 Gate

최초 논증을 검증한 뒤 바로 최종 출력하지 않는다.

### BLOCK — 수정 후 반드시 재검증

다음 중 하나가 `확정`이면 논증을 수정하고 같은 절차를 다시 수행한다.

- 명백한 모순
- 전건 부정 또는 후건 긍정에 의존한 결론
- 핵심 연결 전제 누락
- 결론이 전제보다 명백하게 강함
- 핵심 개념의 의미가 추론 도중 변경됨
- 거짓 양자택일이 결론의 필수 근거임
- 존재하지 않거나 확인되지 않은 법적 연결관계를 사실처럼 추가함

누락 전제를 확인할 수 없다면 만들어 넣지 말고 결론을 조건부로 낮추거나 `확인 필요`로 표시한다.

### WARN — 표현 강도·범위를 조정

- 비정형 자연어 추론
- 사실성 미확인 전제
- 합리적인 반례 가능성
- 복수 해석 가능성
- 법적 전제의 적용범위 불명확

WARN만 있는 경우 최종 출력을 막지는 않지만 단정 수준을 근거 강도에 맞게 조정한다.

### PASS

BLOCK 항목이 없고, 필요한 수정이 반영되었으며, 핵심 전제와 결론의 연결이 설명 가능한 상태다.

## 11. 최종 생성 순서

내부 처리 순서는 다음을 기본으로 한다.

```text
자료·법령 조사
→ 법적 논증 초안
→ 문장·논증 분해
→ 기호화/표준형 변환
→ 전제 검토
→ 추론 타당성 검토
→ 오류·누락·반례 탐색
→ 문단별/전체 평가
→ 갑설·을설 상호 비교
→ BLOCK 수정
→ 논리검증 재수행
→ 출처·현행성·인용 최종 검증
→ 사용자용 최종 문안 생성
```

논리검증 메모, 기호화 표, 점수표, 반례 탐색 과정은 기본 출력에 포함하지 않는다. 사용자가 검증 결과를 요청하면 최종 결론을 뒷받침하는 범위에서 별도의 요약 검증보고서 형태로 제공한다.
