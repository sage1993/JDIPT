# 출력 형식

모든 사용자용 최종 출력은 Markdown으로 작성한다. 사용자가 별도 형식을 명시하지 않으면 **기본 법률검토형**을 사용한다. 법제처 법령해석요청서 등 특정 제출 형식은 사용자가 그 형식을 명시적으로 요청한 경우에만 사용한다.

## 1. 기본 법률검토형 — 기본값

사용자가 별도 형식을 명시하지 않으면 다음 1~8 구조를 정확히 사용한다.

# 1. 제목

# 2. 질의 배경 및 사실관계

# 3. 관련 법령 및 조문

# 4. 해석상 쟁점

# 5. 법률검토

필요한 범위에서 문언해석, 정의·참조규정, 체계적 해석, 목적·연혁, 판례·법령해석례, 가능한 반대해석, 추가 확인 필요사항을 소제목으로 구성한다.

# 6. 질의사항

# 7. 요청취지

# 8. 첨부자료

규칙:
- 사용자가 단순히 `검토해줘`, `법령을 해석해줘`, `질의서 작성해줘`라고 한 경우에는 기본 법률검토형을 사용한다.
- 업로드된 기준 문서가 있어도 사용자가 그 문서의 형식을 따르라고 명시하지 않았다면 1~8 기본 구조를 유지한다. 기준 문서의 문체·논리 전개·표현은 참고할 수 있다.
- 해당 항목에 자료가 없으면 임의로 만들어 채우지 않고 `확인 필요`, `해당 없음`, `제공되지 않음` 등으로 명시한다.

---

## 2. 법제처 법령해석요청서 — 명시적 요청 시에만

사용자가 명시적으로 법제처 법령해석요청서, 법제처 제출용, 또는 `질의요지·갑설·을설` 구조를 요청한 경우에만 다음 1~3 형식으로 전환한다.

# 1. 질의요지

가능하면 다음 구조를 사용한다.

> 「A법」 제○조에서는 …라고 규정하고 있고, 같은 법 시행령 제○조에서는 …라고 규정하고 있는바,
>
> [쟁점에 필요한 최소 전제사실]의 경우, [해석 A]로 보아야 하는지, 아니면 [해석 B]로 볼 수 있는지?

하나의 문언 범위를 묻는 경우:

> …라고 규정하고 있는바, 같은 규정의 “○○”는 △△한 경우만을 의미하는지?

규칙:
- 사실관계는 쟁점에 필요한 최소한만 넣는다.
- 이미 존재하는 처분의 위법성 판단처럼 쓰지 않는다.
- 회신기관이 예/아니오 또는 선택지로 답하기 쉽게 만든다.
- 복합 질문은 서로 독립된 법적 쟁점이면 `가.`, `나.`로 분리한다.

# 2. 해석대상 법령조문 및 관련 법령

## 가. 해석대상 법령조문

질의의 결론을 직접 좌우하는 조문을 원문 그대로 정확히 적는다. 법률뿐 아니라 직접 위임된 시행령·시행규칙이 있으면 함께 넣는다.

## 나. 관련 법령

정의규정, 목적규정, 참조규정, 다른 법률 등 해석에 보조적으로 필요한 조문을 넣는다. 없으면 `해당 없음`으로 쓸 수 있다.

법령명·조문번호·항·호·목을 최신 공식 원문과 대조한다.

# 3. 대립되는 의견 및 이유

## 가. 갑설: [결론을 짧게 요약]

- 문언상 …
- 같은 법 제○조 및 시행령 제○조와의 관계를 보면 …
- 입법 목적·연혁·관련 해석례를 고려하면 …
- 따라서 …

## 나. 을설: [반대 결론을 짧게 요약]

동일한 깊이로 반대 논거를 정리한다. 한쪽 근거가 약하면 약한 이유가 드러나도록 쓴다. 억지 논거를 만들지 않는다.

최종 본문 번호는 1~3만 사용하고 `4. 해석요청기관의 의견`부터 `8. 법령해석요청 체크리스트`까지는 생성하지 않는다.

## 3. Markdown 규칙

- 모든 사용자용 최종 출력은 Markdown으로 작성한다.
- 최상위 항목은 Markdown 제목(`#`) 또는 문서 맥락에 맞는 제목 수준을 일관되게 사용한다.
- 하위 항목은 `##`, `###`, 목록, 표를 사용해 구조를 명확히 한다.
- 법령·판례·법령해석례 등 공식자료는 `references/source-policy.md`에 따라 클릭 가능한 Markdown 인라인 하이퍼링크를 우선 사용한다.
- 사용자가 별도 파일 형식을 요청하지 않는 한 HTML 전용 태그나 일반 텍스트 전용 레이아웃을 기본 출력으로 사용하지 않는다.
