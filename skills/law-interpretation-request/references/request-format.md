# 출력 형식

모든 사용자용 최종 출력은 Markdown으로 작성한다. 사용자가 별도 형식을 명시하지 않으면 **기본 4단 법률검토형**을 사용한다. 법제처 법령해석요청서 등 특정 제출 형식은 사용자가 그 형식을 명시적으로 요청한 경우에만 사용한다.

## 1. 기본 4단 법률검토형 — 기본값

사용자가 별도 형식을 명시하지 않으면 아래 네 개의 최상위 제목을 **문자열과 순서 그대로** 사용한다. 네 항목은 모두 Markdown H1(`#`)이다.

# 1. 질의요지

사용자의 질문이 실제로 무엇을 판단하려는 것인지와 결론에 필요한 최소 사실만 간결하게 정리한다.

규칙:
- 사용자가 직접 질문을 제시했으면 그 법적 판단사항을 우선 반영한다.
- 사용자가 제공하지 않은 사업목적, 처분경위, 기관입장, 당사자의 의도 등을 사실처럼 추가하지 않는다.
- 사실관계가 길더라도 쟁점과 직접 연결되지 않는 내용은 별도 H1으로 분리하지 않는다.
- 결론에 영향을 주는 사실이 누락된 경우 `확인 필요`로 표시한다.
- **1번 항목 이전에는 별도 서론**·요약·검토대상 설명을 작성하지 않는다.

# 2. 검토결론

법적 판단이 가능한 범위에서 **검토결론을 상세 검토이유보다 먼저** 1~3문장으로 제시한다.

규칙:
- `적용됩니다`, `적용되지 않습니다`, `○○로 보는 것이 타당합니다`처럼 사용자가 바로 판단 결과를 파악할 수 있게 쓴다.
- 사실관계 또는 법적 전제가 확정되지 않았으면 단정하지 않고 `○○인 경우에는 …`, `△△ 여부 확인이 필요합니다`와 같이 조건부로 낮춘다.
- 이 항목에서는 장문의 조문 설명이나 해석론을 먼저 전개하지 않는다.
- `# 3. 검토이유` 말미의 결론과 실질적으로 일치해야 한다.

# 3. 검토이유

`references/legal-issue-mapping.md`와 `references/interpretation-principles.md`에서 확인한 분석 결과를 **하나의 연결된 법률논증**으로 작성한다.

기본적인 논리 흐름은 필요한 범위에서 다음을 포함한다.

1. 직접 적용되는 법적 정의·분류 또는 핵심 규정
2. 본칙·예외·특례·적용 제외·준용 등 규정의 구조
3. 관련 규정 사이의 관계
4. 사용자의 사실관계와 법적 요건의 연결
5. 서로 다른 결론을 가르는 실제 문제 발생 지점
6. 필요한 문언·체계·목적·연혁·판례·법령해석례 검토
7. 반대논거가 실질적으로 존재하는 경우 그 논거와 한계
8. `따라서` 등의 방식으로 검토결론 재확인

### Narrative Coherence 규칙

- 내부 분석 단계가 세분화되어 있다는 이유만으로 이를 그대로 사용자용 소제목으로 변환하지 않는다.
- **단일 쟁점**에서는 `법적 정의`, `적용 규정`, `사안 적용`, `문제 발생 지점`, `해석`, `결론`을 각각 별도 소제목으로 기계적으로 분리하지 않는다.
- 정의 → 규정 → 사실대입 → 해석이 하나의 추론 사슬이면 문단을 자연스럽게 연결하여 독자가 앞뒤 관계를 한 번에 파악할 수 있게 한다.
- `# 3. 검토이유` 내부 소제목은 **서로 독립적으로 판단 가능한 복수의 법적 쟁점**이 있을 때만 사용한다.
- 소제목 사용 판단 기준은 해당 제목을 떼어냈을 때 독립적인 법적 질문으로 성립하는지 여부다.
- 불필요한 표와 체크리스트가 문장 간 논리 연결을 끊는 경우에는 문단형 설명을 우선한다.

복수 쟁점 예시는 다음과 같다.

```markdown
# 3. 검토이유

## 가. 기존 건축물에도 해당 기준이 적용되는지

[연속 논증]

## 나. 수직증축과 수평증축의 적용 범위가 다른지

[연속 논증]
```

반대로 한 쟁점의 내부 분석 단계만 다른 경우에는 위와 같이 나누지 않는다.

# 4. 관련 법령 및 자료

검토에 실제 사용한 법령, 조문, 판례, 법제처 법령해석례, 행정규칙, 자치법규, 공문, 도면, 처분서 등 근거자료를 정리한다.

규칙:
- 해석대상 조문과 직접 관련 조문은 현행 공식 원문과 대조한다.
- 법령명·조문·판례·법령해석례 등 공식자료에는 `references/source-policy.md`에 따라 실제 확인한 공식 URL의 Markdown 인라인 하이퍼링크를 우선 적용한다.
- 실제 논증에 사용하지 않은 자료를 형식상 채우기 위해 나열하지 않는다.
- 자료가 없거나 제공되지 않은 경우 `해당 없음`, `제공되지 않음`, `확인 필요` 등으로 표시한다.

기본 출력 규칙:
- 사용자가 단순히 `검토해줘`, `법령을 해석해줘`, `질의서 작성해줘`라고 한 경우에는 기본 4단 법률검토형을 사용한다.
- 최상위 제목은 정확히 `# 1. 질의요지` → `# 2. 검토결론` → `# 3. 검토이유` → `# 4. 관련 법령 및 자료` 순서로 쓴다.
- 검토결론을 검토이유보다 먼저 제시하는 Answer-first 원칙을 유지한다.
- 기본 출력에는 별도 `제목`, `요청취지`, `질의 배경 및 사실관계`, `해석상 쟁점`, `첨부자료` H1을 추가하지 않는다. 필요한 사실·쟁점·자료는 네 항목의 기능에 맞게 통합한다.
- 업로드된 기준 문서가 있어도 사용자가 그 문서의 형식을 따르라고 명시하지 않았다면 4단 기본 구조를 유지한다. 기준 문서의 문체·논리 전개·표현은 참고할 수 있다.
- 해당 항목에 자료가 없으면 임의로 만들어 채우지 않는다.

## 2. 법제처 법령해석요청서 — 명시적 요청 시에만

사용자가 명시적으로 법제처 법령해석요청서, 법제처 제출용, 또는 `질의요지·갑설·을설` 구조를 요청한 경우에만 다음 1~3 형식으로 전환한다.

# 1. 질의요지

가능하면 다음 구조를 사용한다.

> 「A법」 제○조에서는 …라고 규정하고 있고, 같은 법 시행령 제○조에서는 …라고 규정하고 있는바,
>
> [쟁점에 필요한 최소 전제사실]의 경우, [해석 A]로 보아야 하는지, 아니면 [해석 B]로 볼 수 있는지?

하나의 문언 범위를 묻는 경우:

> …라고 규정하고 있는바, 같은 규정의 “○○”는 △△한 경우만을 의미하는지?

규칙:
- 사실관계는 쟁점에 필요한 최소한만 넣는다.
- 이미 존재하는 처분의 위법성 판단처럼 쓰지 않는다.
- 회신기관이 예/아니오 또는 선택지로 답하기 쉽게 만든다.
- 복합 질문은 서로 독립된 법적 쟁점이면 `가.`, `나.`로 분리한다.

# 2. 해석대상 법령조문 및 관련 법령

## 가. 해석대상 법령조문

질의의 결론을 직접 좌우하는 조문을 원문 그대로 정확히 적는다. 법률뿐 아니라 직접 위임된 시행령·시행규칙이 있으면 함께 넣는다.

## 나. 관련 법령

정의규정, 목적규정, 참조규정, 다른 법률 등 해석에 보조적으로 필요한 조문을 넣는다. 없으면 `해당 없음`으로 쓸 수 있다.

법령명·조문번호·항·호·목을 최신 공식 원문과 대조한다.

# 3. 대립되는 의견 및 이유

## 가. 갑설: [결론을 짧게 요약]

- 문언상 …
- 같은 법 제○조 및 시행령 제○조와의 관계를 보면 …
- 입법 목적·연혁·관련 해석례를 고려하면 …
- 따라서 …

## 나. 을설: [반대 결론을 짧게 요약]

동일한 깊이로 반대 논거를 정리한다. 한쪽 근거가 약하면 약한 이유가 드러나도록 쓴다. 억지 논거를 만들지 않는다.

최종 본문 번호는 1~3만 사용하고 `4. 해석요청기관의 의견`부터 `8. 법령해석요청 체크리스트`까지는 생성하지 않는다.

## 3. Markdown 규칙

- 모든 사용자용 최종 출력은 Markdown으로 작성한다.
- 기본 모드의 최상위 4개 항목은 반드시 H1(`#`)으로 출력한다.
- 법제처 모드의 최상위 1~3 항목도 H1(`#`)을 기본으로 사용한다.
- 기본 모드에서는 하위 제목을 과도하게 사용하지 않고 Narrative Coherence 규칙을 우선한다.
- 법제처 모드에서는 하위 항목을 `##`, `###`, 목록, 표로 구조화할 수 있다.
- 법령·판례·법령해석례 등 공식자료는 `references/source-policy.md`에 따라 클릭 가능한 Markdown 인라인 하이퍼링크를 우선 사용한다.
- 사용자가 별도 파일 형식을 요청하지 않는 한 HTML 전용 태그나 일반 텍스트 전용 레이아웃을 기본 출력으로 사용하지 않는다.
